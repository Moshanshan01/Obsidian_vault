# 一、启动流程

**GCC 启动路径：`Reset_Handler` → `SystemInit`（时钟）→ `_start` / 手动数据搬运 → `__libc_init_array`（库和 C++ 构造）→ `main`**
## 1. 硬件复位 → 取栈顶和复位向量

用常见的 **STM32 + GCC（arm-none-eabi）** 工程，编译后会有一个启动文件 `startup_stm32xxxx.s` 和一个链接脚本 `STM32xxxx_FLASH.ld`。

芯片上电，硬件自动从 `0x00000000`（或**BOOT0=0**时通过**总线矩阵**映射到 `0x08000000` 的 Flash）读取两个值：

- 第一个字(0x08000000)：**初始栈顶地址** → 写道 MSP（主堆栈指针）（==这时候栈就可以用啦==）
    
- 第二个字(0x08000004)：**复位向量** → 载入 PC，程序跳转到 `Reset_Handler`
    

这两个值是在链接脚本里定义的，比如栈顶地址常被命名为 `_estack`

## 2. Reset_Handler

在 GCC 的启动文件（通常是 `startup_stm32xxxx.s`）中，复位后首先执行的是 `Reset_Handler`。

### 核心阶段：SystemInit 与 _start

- **SystemInit**：由HAL库提供，通常先调用这个函数来配置时钟系统、使能 FPU 和设置中断向量表偏移等等。
- **_start**：这是 GCC C 库（Newlib 或 Newlib-nano）的入口符号，`_start` ≈ `__main`。
注：ST 官方的启动文件（`startup_stm32xxxx.s`）自己直接在 `Reset_Handler` 里用汇编做了数据搬运、清零，然后直接调 `__libc_init_array` 和 `main`。全程不调用 `_start`，所在**在 STM32 的实际工程里，大概率根本没有用到 `_start`**，而是==手动搬运==。

## 3. 数据搬运与清零：_data_init & _zero_init

在 ARMCC 中，`__main` 自动处理数据搬运。而在 GCC 中，这部分逻辑通常写在启动文件的 `_start` 之后，或者通过链接脚本辅助完成。

GCC 使用以下符号（定义在链接脚本 `.ld` 文件中）来搬运数据：

- **_sidata**：Flash 中存储初始化数据的源地址。
- **_sdata / _edata**：RAM 中数据段的起始和结束地址。
- **_sbss / _ebss**：RAM 中未初始化数据段（BSS段）的起始和结束地址。

**GCC 的汇编逻辑如下：**

1. **复制 .data 段**：把 Flash 里的 `_sidata` 内容复制到 RAM 的 `_sdata` 到 `_edata` 区间。
> 把 Flash 中的拥有初始值的全局/静态变量数据复制到 RAM
> * 源地址：_sidata （Flash 中的 .data 映像起始地址）
> * 目的地址：_sdata 到 _edata （RAM 中 .data 段的起始和结束地址）
> * 过程：每次复制 4 字节，直到所有 .data 拷贝完毕
	
2. **清零 .bss 段**：把 RAM 的 `_sbss` 到 `_ebss` 区间全部填 0。
> 把 RAM 中的未初始化/零初始化的全局变量的数据段填 0
> * 范围：_sbss 到 _ebss （BSS 段的起始和结束地址）
> * 过程：每次写入 4 字节的 0，直到全部清零


## 4. 库初始化与构造函数：__libc_init_array

ARMCC 的 `__rt_entry` 在 GCC 中对应的主要是 `__libc_init_array`。

- 它会初始化 C 库（里面会准备堆（`sbrk` 所需的边界），供 `printf` / `malloc` 之类用）。
- 它会遍历链接器生成的数组，调用所有全局对象的 **C++ 构造函数**（即 `.init_array` 段中的函数）,  如果只用 C 语言，这一部分实际上是空遍历，没有开销_。

## 5. 进入用户代码：main

最后，调用 `bl main` 进入你的 `main()` 函数。

## 6. 总结对比表

|阶段|ARMCC (Keil) 做什么|GCC (arm-none-eabi) 做什么|**注意区别**|
|---|---|---|---|
|数据搬运|`__main` 库函数自动处理（看不见）|启动文件里用汇编循环，配合链接脚本符号显式完成（看得见）|GCC 更透明，方便调试；ARMCC 更自动化|
|零初始化|`__main` 内部完成 ZI 段清零|启动文件里用汇编循环清零 `.bss`|功能相同|
|堆栈设置|`__user_setup_stackheap` 设置栈和堆（可重写）|栈顶在向量表（`_estack`），堆在库初始化时通过 `_sbrk` 设定|堆的定制方式不同，但结果一样|
|库和构造函数|`__rt_entry` 调用库初始化 + C++ 构造|`__libc_init_array` 调用 `.init_array` 段中的函数|名称不同，但职责一样|
|内存布局描述|散列文件 `.sct`|链接脚本 `.ld`|语法完全不同|
|入口符号|启动文件跳转到 `__main`|启动文件自己做完搬运，跳转到 `__libc_init_array` 然后 `main`|流程顺序相同，跳转目标不同|

所以，如果你在看 GCC 的启动代码，你不会看到 `__main`，而是会看到一大段汇编代码在搬运数据，紧接着调用 `__libc_init_array`，最后才是 `main`。

# 二、补充：
## 1. Reset_Handler 做了什么？

```assembly file="startup_stm32xxxx.s" fold


Reset_Handler:
    /* ---- 1. 再次设置栈顶指针（保险措施） ---- */
    ldr   sp, =_estack         @ 把栈顶地址 0x20020000 加载到主堆栈指针 SP(MSP)
                               @ 硬件复位时已经从向量表自动加载过一次，这里再写一次保证可靠


    /* ---- 2. 初始化系统时钟（ST 库函数） ---- */
    bl    SystemInit           @ 调用 SystemInit()，配置时钟树、使能 FPU 等
                               @ 该函数由 ST 的 HAL/标准库提供，与编译器无关


    /* ---- 3. 搬运 .data 段：把 Flash 中的初始化数据复制到 RAM ---- */
    ldr   r0, =_sdata          @ 将 RAM 中 .data 段起始地址加载到 r0（目的指针）
    ldr   r1, =_edata          @ 将 RAM 中 .data 段结束地址加载到 r1（结束条件）
    ldr   r2, =_sidata         @ 将 Flash 中 .data 初始值存放地址加载到 r2（源指针）
    b     LoopCopyDataInit     @ 跳转到循环比较，开始逐字拷贝


CopyDataInit:
    ldr   r3, [r2], #4        @ 从源地址 [r2] 读取 4 字节到 r3，然后 r2+=4（源指针后移）
    str   r3, [r0], #4        @ 把 r3 的值存入目的地址 [r0]，然后 r0+=4（目的指针后移）
LoopCopyDataInit:
    cmp   r0, r1              @ 比较目的指针是否已到达结束地址
    bcc   CopyDataInit        @ 如果 r0 < r1 (无符号小于)，继续拷贝下一个字


	/* ---- 4. 清零 .bss 段：把 RAM 中的未初始化/零初始化数据段填 0 ---- */
    ldr   r0, =_sbss           @ 将 BSS 段起始地址加载到 r0（目的指针）
    ldr   r1, =_ebss           @ 将 BSS 段结束地址加载到 r1（结束条件）
    mov   r2, #0               @ r2 = 0，作为清零用的常数
    b     LoopFillZerobss      @ 跳转到循环比较


FillZerobss:
    str   r2, [r0], #4        @ 将 0 写入目的地址 [r0]，然后 r0+=4（指针后移）
LoopFillZerobss:
    cmp   r0, r1              @ 比较当前指针是否已到达结束地址
    bcc   FillZerobss         @ 如果 r0 < r1，继续清零下一个字


    /* ---- 5. 初始化 C 库和 C++ 全局构造函数 ---- */
    bl    __libc_init_array    @ 调用库函数，用来：
                               @   a) 初始化 Newlib 标准库（设置堆、stdin/stdout 等）
                               @   b) 遍历 .init_array 段，调用每个全局对象的构造函数


    /* ---- 6. 进入用户 main 函数 ---- */
    bl    main                 @ 调用用户的 main() 函数
    bx    lr                   @ 从 main 返回时，跳转到 LR 中的地址（通常不会返回到这里）

```


**新手注意**：你看到的 `_sdata`、`_edata`、`_sidata`、`_sbss`、`_ebss` 这些符号，**不是芯片定义的，而是链接脚本提供的地址标签**。

## 2. 链接脚本里的秘密 —— 那些符号是怎么来的？

链接脚本（`.ld`）决定了内存布局。我们截取一段看：

```ld file="STM32F411XX_FLASH.ld" fold

MEMORY
{
  FLASH (rx) : ORIGIN = 0x08000000, LENGTH = 512K   /* Flash 地址：从 0x08000000 开始，共 512K */
  RAM  (rwx) : ORIGIN = 0x20000000, LENGTH = 128K   /* RAM  地址：从 0x20000000 开始，共 128K */
}

SECTIONS
{
  /* 代码段：所有函数编译出来的机器码，全扔进 Flash */
  .text : { *(.text) } > FLASH

  /* 只读数据：比如 const 常量、字符串，也扔进 Flash */
  .rodata : { ... } > FLASH

  /* 
   * 数据段：有初值的全局变量（比如 int a = 5;）
   * 初值得烧在 Flash 里，运行时变量要在 RAM 里，这样你才能修改它
   * 所以这一段在 RAM 里跑，但初值备份在 Flash 里 (AT 后面那堆就是初值的 Flash 位置)
   */
  .data : AT ( ADDR (.rodata) + SIZEOF (.rodata) )
  {
    _sdata = .;          /* 变量在 RAM 里的起点 */
    *(.data)             /* 所有 .data 变量都放这里 */
    _edata = .;          /* 变量在 RAM 里的终点 */
  } > RAM                 /* 这句表示：运行时这段在 RAM 里 */

  /* _sidata 就是初值在 Flash 里的起点，启动代码会用它来搬运 */
  _sidata = LOADADDR (.data);

  /* 
   * BSS 段：未初始化或初始化为 0 的全局变量（比如 int b; 或 int c=0;）
   * 不需要在 Flash 里占空间，只要在 RAM 里留一块，启动时全部清成 0
   */
  .bss :
  {
    _sbss = .;           /* 要清零的 RAM 起点 */
    *(.bss)              /* 所有 BSS 变量 */
    _ebss = .;           /* 要清零的 RAM 终点 */
  } > RAM

  /* 栈顶地址 = RAM 的最后一个地址，栈从 RAM 末尾向下长 */
  _estack = ORIGIN(RAM) + LENGTH(RAM);
}

```

关键点：
- _sdata / _edata 标记 RAM 里数据段的范围。
	
 - _sidata 指向 Flash 中那一份 用于初始化 .data 的常量数据。
	
- 启动代码循环做的事就是：`for (src = _sidata, dst = _sdata; dst < _edata; src++, dst++) *dst = *src;`
	
- 清零 .bss 类似：`for (p = _sbss; p < _ebss; p++) *p = 0;`

>🔵 ARM 编译器（Keil）的区别①
>  在 Keil 里，你不做链接脚本，而是用 散列加载描述文件（.sct）。数据搬运逻辑完全被封装在 __main 库函数里，你看不到那段汇编循环。对新手来说，GCC 的写法更透明，但 Keil 的写法更“自动化”。
