上面两张图片是专门针对使用 **ARM 编译器（ARMCC/ARMCLANG）** 的 Keil MDK 环境。它把“宏观调用流程”和“库函数内部隐秘细节”彻底缝合，还原一个完整的真相。

# 第一阶段：硬件自动完成（你完全不可见）

流程的起点是硬件，不需要任何软件参与。按下复位键或上电的瞬间，Cortex-M 内核的硬件逻辑自动执行以下动作：

1.  **取栈顶地址**：从存储器地址 `0x00000000`（通常映射到 Flash 的 `0x08000000`）读取第一个字（4字节），这个值就是**初始栈顶指针**，硬件自动将其加载到 **MSP（主堆栈指针）** 寄存器。此时，栈是空的，栈顶就是 SP 的初始值。

2.  **取复位向量并跳转**：从紧挨着的地址 `0x00000004`（`0x08000004`）读取第二个字，这是**复位向量**，即 `Reset_Handler` 的入口地址。硬件将此地址加载到 **PC（程序计数器）** 寄存器，CPU 就此开始执行 `Reset_Handler` 里的代码。

# 第二阶段：Reset_Handler 宏观调用（启动文件可见）

现在，程序的控制权正式交到了你工程里启动文件（`startup_xxx.s`）手中的 `Reset_Handler` 函数。你可以在代码里看到这个部分，它负责流程顶层调度。

1.  **保险动作**：`Reset_Handler` 做的第一件事，通常是再次显式地把栈顶地址 `__initial_sp` 加载到 MSP 寄存器（`LDR R0, =__initial_sp; MSR MSP, R0`），确保万无一失。

2.  **系统时钟初始化**：调用一个名为 **`SystemInit()`** 的函数。这个函数不在编译器的库里，而是在你工程目录下的 `system_xxx.c` 文件中，由芯片厂商提供。它负责配置芯片的时钟树（晶振、PLL、系统时钟HCLK、外设时钟PCLK等）。此函数执行完毕后，芯片才以你期望的正常主频运行，并返回到 `Reset_Handler`。

3.  **跳转到 C 库大管家 `__main`**：`Reset_Handler` 的最后一项工作，就是执行一条跳转指令，调用编译器提供的 **`__main`** 函数。注意，这不是你写的 `main`，它是 C 库初始化代码的入口点，至此启动文件完成使命。

# 第三阶段：`__main` 内部的隐秘细节（ARMCC C 库内部，不可见）

从这个阶段开始，全是被 ARMCC 运行库高度封装的细节，源码不可见。我们为你拆解 `__main` 内部实际上做了哪些工作：

1.  **数据段搬运（Copy Code and Data）**：`__main` 会搬运 **RW 数据段**。它把那些有明确非零初值的全局变量（比如 `int a = 5;`）的初始化数据，从 Flash 的加载地址（`_sidata` 附近）忠实地复制到 RAM 里的运行时地址（`_sdata` 到 `_edata` 区间去）。这就是为什么这些变量的值在程序一开始就是对的。

2.  **零初始化段清零（Initialize ZI Data）**：紧接着，它会处理 **ZI 数据段**。把未初始化或初始化为零的全局变量（比如 `int b;`）所在的 RAM 区域（BSS 段）全部清零。这解释了为什么这类变量默认值一定是 0。

3.  **调用运行时入口 `__rt_entry`（Runtime Entry）**：在完成上述数据内存的初始化后，`__main` 内部会调用 **`__rt_entry`**，这个函数负责建立 C 语言程序所需的完整运行时环境。
    *   **设置堆和栈**：调用 `__user_setup_stackheap` 函数，正式初始化堆（Heap）和栈（Stack）的边界寄存器，为动态内存分配和函数调用提供保障。
    *   **初始化 C 库**：配置 C 标准库所需的相关底层（如 `__rt_lib_init`），让你之后在 `main` 里能顺利使用 `printf`、`malloc` 等功能。
    *   **调用 C++ 全局对象构造函数**：如果你使用了 C++，它会遍历并执行所有全局和静态对象的构造函数（`.init_array` 段中的函数）。

# 第四阶段：进入用户世界

1.  **调用 `main()`**：当 `__rt_entry` 完成所有幕后工作后，它终于愉快地调用用户编写的 **`main()`** 函数。

2.  **用户代码运行**：此时，堆栈有了、时钟配好了、全局变量的初值都对了、C 库也能用了。你的应用程序正式开始在绝对安妥的环境下运行。

---

**一句话总结**：硬件只管最开始两步，`Reset_Handler` 负责时钟并找到库的大管家 `__main`，而 `__main` 内部则通过搬运数据、内存清零、调用 `__rt_entry` 建立环境等一整套隐秘流程，为你铺好一切，最后再把你请进 `main` 里。
