## 一、工具作用

- Doxygen  
    👉 解析代码结构，生成文档 + 调用关系
    
- Graphviz  
    👉 负责画图（调用图 / 依赖图）
    

👉 类似 SciTools Understand 的“轻量替代方案”

```bash
sudo pacman -S doxygen graphviz
```


# 四、核心配置，按需修改（嵌入式推荐）
```text
# Doxygen 配置文件（嵌入式优化版）

# ================= 借助clang分析=================
# 先别用，待考察
#  启用 Clang 辅助解析
# CLANG_ASSISTED_PARSING = YES

# 指定 compile_commands.json 所在的目录
# CLANG_DATABASE_PATH = build/Debug/compile_commands.json

# ================= 基本设置 =================
# 当 CLANG_ASSISTED_PARSING 生效后，INPUT 和 INCLUDE_PATH 这两个配置可以被大大简化，甚至留空
# 输入目录（. 表示当前工程根目录）
INPUT = .

# 递归扫描子目录
RECURSIVE = YES

# 排除目录（防止分析编译产物）
EXCLUDE = build/ docs/ .git/ cmake-build-debug/

# 只分析 C/C++ 源文件
FILE_PATTERNS = *.c *.h

# ================= 提取内容 =================
# 提取所有代码（不需要写注释也能生成文档）
EXTRACT_ALL = YES

# 提取 static 函数（嵌入式很重要）
EXTRACT_STATIC = YES

# 提取私有内容
EXTRACT_PRIVATE = YES

# ================= 图生成 =================
# 开启 Graphviz 支持
HAVE_DOT = YES

# 显示函数调用关系（我调用谁）
CALL_GRAPH = YES

# 显示被调用关系（谁调用我）
CALLER_GRAPH = YES

# 控制图复杂度（防止太乱）
DOT_GRAPH_MAX_NODES = 50

# ================= 宏处理 =================
# 开启预处理（解析宏）
ENABLE_PREPROCESSING = YES

# 展开宏
MACRO_EXPANSION = YES

# 不限制宏展开范围
EXPAND_ONLY_PREDEF = NO

# STM32 宏（根据芯片修改）
PREDEFINED += STM32F4xx USE_HAL_DRIVER

# ================= 输出 =================
# 生成 HTML 文档
GENERATE_HTML = YES

# 输出目录
OUTPUT_DIRECTORY = docs

# 中文界面
OUTPUT_LANGUAGE = Chinese

```
# 五、生成文档

```bash
doxygen Doxyfile
```

打开：

```bash
xdg-open docs/html/index.html
```

# 七、🚀 进阶用法与自动化

## 1️⃣常用CLANG_OPTIONS

在 `Doxyfile` 中，你也可以通过 `CLANG_OPTIONS` 为 Clang 解析器传递额外参数。例如：
```text

# 为 Clang 解析器添加额外的编译选项
CLANG_OPTIONS = -std=c++11
```

## 2️⃣集成到CMake构建

你可以将 Doxygen 的生成过程自动化，作为 CMake 构建系统的一部分。在你的 `CMakeLists.txt` 文件中添加如下代码：

```cmake

# 在 CMakeLists.txt 中集成 Doxygen
find_package(Doxygen)
if(DOXYGEN_FOUND)
    # 配置你的 Doxyfile.in，并添加自定义目标
    configure_file(${CMAKE_CURRENT_SOURCE_DIR}/Doxyfile.in ${CMAKE_CURRENT_BINARY_DIR}/Doxyfile @ONLY)
    add_custom_target(doc
        ${DOXYGEN_EXECUTABLE} ${CMAKE_CURRENT_BINARY_DIR}/Doxyfile
        WORKING_DIRECTORY ${CMAKE_CURRENT_BINARY_DIR}
        COMMENT "Generating API documentation with Doxygen" VERBATIM
    )
endif()
```
之后，你就可以通过 `make doc` 命令来生成文档。

### 📖 逐句解析

#### 1. `find_package(Doxygen)`
- **作用**：CMake 会去系统中查找 Doxygen 是否已安装。如果找到，它会设置几个变量，比如：
  - `DOXYGEN_FOUND` 为 `TRUE`
  - `DOXYGEN_EXECUTABLE` 为 `doxygen` 命令的完整路径（通常是 `/usr/bin/doxygen`）
- **结果**：如果没找到，后面的 `if(DOXYGEN_FOUND)` 块就不会执行，不会报错中断构建，而是静默跳过。

---

#### 2. `if(DOXYGEN_FOUND)` ... `endif()`
- **作用**：只有系统确实安装了 Doxygen 时，才执行里面的文档生成配置。这是一种**防御性编程**，避免因为缺少 Doxygen 导致 CI 构建失败。
- **可以怎么改**：你也可以改成这样，强制要求必须有 Doxygen：
  ```cmake
  find_package(Doxygen REQUIRED)   # 如果找不到，直接报错终止 CMake 配置
  ```

---

#### 3. `configure_file(...)`
```cmake
configure_file(${CMAKE_CURRENT_SOURCE_DIR}/Doxyfile.in
               ${CMAKE_CURRENT_BINARY_DIR}/Doxyfile
               @ONLY)
```
- **作用**：把模板文件 `Doxyfile.in` 复制到构建目录，并**替换里面的 CMake 变量**。
- **参数说明**：
  - **`${CMAKE_CURRENT_SOURCE_DIR}/Doxyfile.in`**：源模板文件路径。你需要在项目根目录（和 `CMakeLists.txt` 同级）放一个 `Doxyfile.in`。
  - **`${CMAKE_CURRENT_BINARY_DIR}/Doxyfile`**：生成的目标文件路径（在构建目录下）。生成后的文件名就是 `Doxyfile`，可以直接被 doxygen 读取。
  - **`@ONLY`**：只替换形如 `@VAR@` 的占位符，不替换 `${VAR}`。这样可以避免和 Doxygen 自身的变量语法冲突。
- **为什么用模板？**  
  你可以在模板文件里使用 CMake 变量来动态设定某些路径，比如：
  ```
  OUTPUT_DIRECTORY       = @CMAKE_CURRENT_BINARY_DIR@/docs
  INPUT                  = @CMAKE_CURRENT_SOURCE_DIR@/Core/Src
  PROJECT_NUMBER         = @PROJECT_VERSION@
  ```
  这样你的文档路径会跟随项目名称、版本自动变化，而不用手动去改。

---

#### 4. `add_custom_target(doc ...)`
```cmake
add_custom_target(doc
    ${DOXYGEN_EXECUTABLE} ${CMAKE_CURRENT_BINARY_DIR}/Doxyfile
    WORKING_DIRECTORY ${CMAKE_CURRENT_BINARY_DIR}
    COMMENT "Generating API documentation with Doxygen" VERBATIM
)
```
- **作用**：创建一个名为 `doc` 的**伪目标**（不是实际的二进制文件）。当你执行 `make doc`（或 `cmake --build . --target doc`）时，它会运行 Doxygen。
- **参数说明**：
  - **`${DOXYGEN_EXECUTABLE} ${CMAKE_CURRENT_BINARY_DIR}/Doxyfile`**：实际执行的命令行，等价于在构建目录下手动输入 `doxygen Doxyfile`。
  - **`WORKING_DIRECTORY ${CMAKE_CURRENT_BINARY_DIR}`**：命令执行的工作目录。这里设置为构建目录，这样 Doxygen 就能在当前路径找到你刚刚生成的 `Doxyfile`，并且文档输出的相对路径也会基于此目录。
  - **`COMMENT "..."`**：在运行命令前，CMake 会打印这条信息，比如 `[ 0%] Generating API documentation with Doxygen`，让你知道当前在做什么。
  - **`VERBATIM`**：确保命令中的参数正确转义，避免空格等特殊字符引起问题。这是一个推荐的最佳实践。

**运行方式**：
- 如果你是 Makefile 生成器：`make doc`
- 如果是 Ninja：`ninja doc`
- 通用的：`cmake --build <build_dir> --target doc`
