## 一、 ADC的基本原理

**1. 什么是ADC？**
![](assets/10.%20ADC/file-20260426205507166.png)
- ADC (Analog-to-Digital Converter)，即模拟/数字转换器。它把连续变化的模拟电压信号，转换成离散的数字信号（0和1），供单片机处理。
- **逐次逼近型（SAR）ADC** 先将输入模拟电压采样并保持（电容充电然后断开），然后由逐次逼近寄存器控制一个内部数模转换器（DAC），采用“二分试探法”从最高位到最低位逐位确定数字码：每一位先置“1”，使 DAC 输出一个试探电压，与输入的采样电压比较；若 DAC 输出高于输入，比较器输出为 0，则将该位清“0”，否则保留“1”。如此完成 N 次比较（N 为分辨率，如 12 位 ADC 需要 12 个逐次逼近周期），最终寄存器中的数字量即代表输入电压的转换结果。

**2. 时钟和ADC的几个核心参数：**
* **ADC 时钟 (`ADCCLK`)**
  - 来源于 APB2 时钟（PCLK2）经分频器产生。
  - 不能超过 **36 MHz**（F4 系列，保证性能）， 保证采样是电容完全充电。  
  - 通常配置为 PCLK2/4 或 PCLK2/8，例如 PCLK2=84MHz 时，`/4` 得到 21MHz。  
  - 采样周期时间与 ADCCLK 有关：`采样总时间 = 采样周期数 + 12 个周期`（对 12 位分辨率）。
*   **分辨率：** STM32F4的ADC通常是**12位**的。这意味着它能把参考电压分成 $2^{12} = 4096$ 个阶梯。
    *   *计算公式：* `实际电压 = (ADC读取值 / 4095) × 参考电压`
    *   *注意：* 如果参考电压是3.3V，那么它的最小分辨能力（1 LSB）约为 $3.3V / 4096 \approx 0.8mV$。
*   **参考电压 ($V_{REF}$):** 测量的基准。F4通常直接使用VDDA（模拟电源，一般是3.3V），也可以通过VREF+引脚外接高精度基准电压源。
*   **采样时间 (`Sampling Time`)：** ADC内部有一个小电容，采样时需要给这个电容充电，充满后再断开电源开始转换。如果信号源内阻较大，充电慢，就需要**延长采样时间**，否则转换结果会偏小且不准。
*   **转换时间：** STM32F4的ADC时钟最高可达36MHz。在12位分辨率下，最快转换时间为：`采样时间 + 12个ADC时钟周期`。

## 二、 STM32F4的ADC硬件特性

STM32F4系列通常配备了 **1到3个ADC**（根据具体型号而定，如F407有3个），主要特性如下：
1.  **分辨率可调：** 12位、10位、8位、6位（通常用12位）。
2.  **多通道：** 每个ADC有多达16个外部通道（对应不同的GPIO引脚），还有内部通道（如温度传感器、内部参考电压 $V_{REFINT}$）。
3.  **多种触发方式：** 软件触发（写寄存器）或硬件触发（定时器PWM触发、外部中断线触发——常用于控制采样率）。
4.  **双重/三重模式：** ADC1、ADC2、ADC3可以协同工作，实现交织、同步采样等高级功能（初学可暂不深究）。

## 三、转换模式概览

- **单次转换**：软件触发一次，转换完成后停止。适合低功耗、不频繁采样。
    
- **连续转换**：一次转换完成后立即开始下一次。常配合扫描模式使用。
    
- **扫描模式**：如果使能，ADC 会按次序扫描规则组的所有通道。若不使能，则只转换第一个通道。
    
- **间断模式（Discontinuous）**：每次触发只转换一部分通道（比如一次只转 2 个），分多次完成全部扫描。
    

**常用组合**：

- 单通道单次转换：最简单，不需要 DMA，直接读结果。 
- 多通道连续扫描 + DMA：最常用，连续自动采集多个通道，数据由 DMA 存入数组。
- 注：在扫描模式下，必须配合 **DMA（直接内存访问）** 来搬运数据，否则后一个通道转换的数据会覆盖前一个通道的数据，你只能读到最后一个通道的值。

## 四、关键概念：规则组与注入组
**一句话抓住本质**

- **规则组**：像“常规任务队列”，按顺序自动采集多个通道，主要用于周期性、大批量的数据采集。
    
- **注入组**：像“紧急中断任务”，可以随时**强行插入**到正在进行的规则组转换中，优先处理少数关键信号。

**核心区别对照表**

||规则组（Regular）|注入组（Injected）|
|---|---|---|
|**工作方式**|顺序扫描，按 Rank 依次转换|触发后立即插入执行，类似中断抢占|
|**触发源**|软件启动、连续自动、定时器等|独立的触发源（外部引脚、定时器、软件）|
|**通道数量**|最多 16 个|最多 4 个|
|**数据寄存器**|共 **一个** DR，多通道必须配合 DMA 才能不丢数据|每个通道有 **独立** 寄存器（JDR1~JDR4），无需 DMA 也能安全读取|
|**优先级**|低，可被注入组打断|高，执行完注入组才恢复规则组|
|**典型场景**|常规电压、温度、环境光等慢速采集|电机过流、电源故障、外部急停等需要极低延迟的紧急信号|

**额外必知细节（加深理解）**

1. **注入组的“注入”时机**：当规则组正在转换时，一旦注入组被触发，ADC 不会立即中断当前正在转换的规则通道，而是**等到当前这一个通道转换结束**，然后立即切换到注入组，把配置好的注入通道全部转换完毕，再无缝返回到规则组的下一个 Rank 继续转换。因此注入组延迟极小（最多等待一个规则通道的转换时间）。
    
2. **数据安全性**：由于注入组每个通道都有独立的寄存器（JDR1~JDR4），你可以随时读取最新的采集值，不用担心像规则组那样被下一个通道覆盖。这也是为什么注入组可以不依赖 DMA。
    
3. **触发独立性**：注入组可以绑定到一个完全独立的触发事件上（比如定时器捕获/比较事件、外部中断），这使得它非常适合用来做硬件条件驱动的紧急检测，而无需 CPU 干预就能自动记录异常瞬间的电压。
    
4. **配置方式差异**：在 HAL 库中，规则组用 `HAL_ADC_ConfigChannel` 设置 Rank；注入组需要用 `HAL_ADCEx_InjectedConfigChannel` 设置注入顺序和触发沿，启动时调用 `HAL_ADCEx_InjectedStart` 等函数。

## 四、 STM32CubeMX 与 HAL库配置步骤

### 步骤 1：时钟与GPIO配置
*   **ADC时钟：** F4的ADC时钟不是直接来自APB2，而是经过分频器（分频系数可为2/4/6/8）。**ADC时钟最高不能超过36MHz**。
*   **GPIO：** 将需要用到的引脚配置为 **Analog Mode（模拟模式）**。

### 步骤 2：ADC参数配置 (核心)
![](assets/10.%20ADC/file-20260426232529966.png)
在CubeMX的 `ADCx` 配置中：
*   **Resolution:** 设定 ADC 转换结果的位数，位数越低转换速度越快，默认选 `12 bits`。
* **Data Alignment:** 数据对齐方式，选右对齐，数据存放在寄存器的低 12 位 (bit 0-11)，高 4 位清零。
*   **Scan Conversion Mode:** 如果只测单通道选 `Disable`；多通道必须选 `Enable`。
*   **Continuous Conversion Mode:** 根据需求选 `Disable`（单次）或 `Enable`（连续， 一次触发后 ADC 会持续反复转换）。
*   **Discontinuous Conversion Mode:** 间断模式，使能后，一次触发只转换序列中的 1 个（或 N 个）通道，而不是整个序列（初学一般 `Disable`）。
* **DMA Continuous Requests:** 这样每个通道转换完成，硬件都会自动产生一次 DMA 请求，立即将 DR 数据搬走，不会被下一个通道覆盖。关闭后只在序列最后一个通道转换完成时产生一次 DMA 请求。
* **End Of Conversion Selection:** 转换结束标志选择：
  - **单通道转换结束时置位**：每转换完一个通道，EOC 标志就置位，触发中断（不是DMA）。
  - **序列转换结束时置位**（推荐）：只有在扫描完所有设定的通道后，EOC 标志才置位，触发中断（不是DMA）。
*   **Number of Conversion:** 如果开了扫描，这里填你要转换的通道总数（如用了3个通道就填3）。
*   **External Trigger Conversion Source:** 选 `Software Trigger`（软件触发）或 `Timer X Trigger Out`（定时器触发，用于固定频率采样）。
* **External Trigger Conversion Edge:** 是上升沿、下降沿还是双边沿触发，若上面选择了软件触发启动ADC，则选择`None`。
*   **Rank和Channel配置:** **Rank (序号)** 和 **Channel (通道选择)** 定义了“先做什么、后做什么”。并设置**采样时间**。
    *   *经验：* 如果是高阻抗信号（比如分压电阻较大），充电时间越长，采样时间设长一点（如 `56 Cycles` 或更高）；如果是低阻抗信号，可以设短一点（如 `3 Cycles`）提高速度。
* **Number Of Conversions:** 注入组配置，注入组可以打断普通规则组采集，**初学者暂时不需要**配置为0即可！
* **WatchDog（模拟看门狗）:** 
  - 一个**硬件电压监控器**。你可以设置一个电压上限和下限，一旦规则组的某个通道采到的电压超出这个范围，ADC 能自动产生一个中断。
  - **典型用法**：监控电池电压，低了就报警；或者监控某个传感器，短路/开路就立刻响应。

### 步骤 3：DMA配置（多通道必看）
如果开启了扫描模式（多通道），必须在CubeMX中开启ADC的DMA：
*   **Mode:** `Normal`（单次传输完停止） 或 `Circular`（循环传输，**最常用**）。
- **Increment Address:** 地址自增，因为ADC只有一个数据寄存器，所以**取消勾选** `peripheral`；`Memory`根据需要勾选。
*   **Data Width:** Peripheral（外设，即ADC）选 `Half Word (16 Bits)`，Memory（内存变量）也选 `Half Word (16 Bits)`（因为12位数据存放在16位变量里最方便）。

## 五、 常用代码逻辑

### 场景 A：单通道，单次/连续采集（不用DMA）
```c
uint32_t adc_value = 0;
float voltage = 0.0;

// 1. ADC 校准必须做：电源刚上电或 ADC 刚使能时，不做校准偏移会很大。效果是把 ADC 的“尺子刻度”做均匀，消除转换特性的偏移和线性误差，注意⚠️校准的不是参考电压！
HAL_ADC_Stop(&hadc1);             // 校准前需停止 ADC
HAL_ADCEx_Calibration_Start(&hadc1, ADC_SINGLE_ENDED); // 会阻塞等待硬件校准完成，不能跳过

// 2. 启动ADC, 连续采集只需要启动一次
HAL_ADC_Start(&hadc1);

// 3. 等待转换完成（可以加超时时间，如100ms）
// 如果是连续采集，这个函数每次调用只等当前这一次转换完
HAL_ADC_PollForConversion(&hadc1, 100);

// 4. 检查是否转换成功 (EOC标志)
if(HAL_IS_BIT_SET(HAL_ADC_GetState(&hadc1), HAL_ADC_STATE_REG_EOC))
{
    // 4. 获取转换后的数字量
    adc_value = HAL_ADC_GetValue(&hadc1);
    
    // 5. 计算实际电压
    voltage = (adc_value / 4095.0f) * 3.3f;
}

// 如果是单次转换，用完后可以关闭省电
// HAL_ADC_Stop(&hadc1);
```

### 场景 B：多通道，连续采集（配合DMA，最常用）
```c
// 1. 定义数组存放多通道结果（假设有3个通道）
#define ADC_CHANNEL_NUM 3
uint16_t adc_values[ADC_CHANNEL_NUM]; 

// 2. ADC 校准必须做：电源刚上电或 ADC 刚使能时，不做校准偏移会很大。效果是把 ADC 的“尺子刻度”做均匀，消除转换特性的偏移和线性误差，注意⚠️校准的不是参考电压！
HAL_ADC_Stop(&hadc1);
HAL_ADCEx_Calibration_Start(&hadc1, ADC_SINGLE_ENDED);

// 3. 在初始化代码(MX_ADC1_Init之后)或main函数开头启动DMA
HAL_ADC_Start_DMA(&hadc1, (uint32_t*)adc_values, ADC_CHANNEL_NUM);

// 4. 之后在需要的地方直接读取数组即可
// 注意：adc_values[0]对应Rank 1配置的通道，以此类推
HAL_ADC_PollForConversion(&hadc1, 100);
float ch1_vol = (adc_values[0] / 4095.0f) * 3.3f;
float ch2_vol = (adc_values[1] / 4095.0f) * 3.3f;
```

### 场景 C：使用ADC中断（单通道时可用）
如果你不想用 `PollForConversion` 阻塞等待，可以开启ADC中断：
```c
// 初始化时
HAL_ADC_Start_IT(&hadc1);

// 在stm32f4xx_it.c中（或者重写回调函数）
void HAL_ADC_ConvCpltCallback(ADC_HandleTypeDef* hadc)
{
    if(hadc->Instance == ADC1)
    {
        uint16_t val = HAL_ADC_GetValue(hadc);
        // 处理数据...
    }
}
```

## 六、 实战踩坑与避坑指南（非常重要！）

1.  **ADC数据对齐问题：**
    默认是**右对齐**，读出来的数据直接就是0~4095。如果你不小心在CubeMX里勾选了左对齐，读出来的数据会非常大（左移了4位），计算电压时记得要除以4095（而不是65535），或者右移4位再算。
2.  **GPIO模式没选对：**
    如果引脚配置成了输入或输出，ADC是读不到正确电压的（通常读到0或4095）。**必须选 Analog！**
3.  **硬件上的干扰：**
    *   ADC非常敏感。如果板子上有开关电源、电机驱动，ADC读数会乱跳。
    *   **对策：** 硬件上在ADC输入端并联一个 0.1uF 的小电容到地（做低通滤波）；软件上做**均值滤波**（连续读10次求平均）。
4.  **内部参考电压 ($V_{REFINT}$) 的妙用：**
    有时你觉得板子的3.3V不精准（比如实际只有3.2V），怎么校准？
    F4内部有一个固定的参考电压通道（通常是通道17，约1.2V）。你可以同时采集外部信号和内部 $V_{REFINT}$，利用1.2V是固定不变的原理，反向推算出此时真实的VDDA电压： $V_{REF}$ = 1.2f * （4095.0f / 采集到的内部参考电压数字量），从而校准外部通道的电压值。
5.  **不要在DMA传输中途修改数组：**
    如果DMA配置为Circular模式，它会在后台不断刷新 `adc_values` 数组。如果你在 `main` 的 `while(1)` 里直接对这个数组做复杂运算，可能会读到“半个新数据半个旧数据”的错乱情况。
    *   **对策：** 关闭DMA中断一瞬间拷贝数组，或者直接使用双缓冲。


## 七、补充
### 软件双缓冲（Ping-Pong）
- #### 核心原理：
  - 准备一个大的独立缓冲区平分为上下两部A和B，让它们交替工作！
  - DMA 往 **缓冲区 A** 写入时，CPU **安全处理**刚填满的**缓冲区 B**。
  - DMA 写满了 A，**立即自动切换到 B** 继续写，同时通知 CPU："A 满了，来处理"。
  - CPU 处理 B、DMA 写 A，如此循环，无缝衔接，采集永不中断。
<br>
- #### 核心机制：
  - **半传输中断（HTIF）**：DMA 计数器从初始值降到一半时触发 → 表示**缓冲区前半段**刚被填满，CPU 可安全处理前半段的数据。
  - **传输完成中断（TCIF）**：DMA 计数器归零时触发 → 表示**缓冲区后半段**刚被填满，CPU 可安全处理后半段的数据。
  - 在 HAL 库中，这两个中断分别对应两个回调函数：
    ```c
    void HAL_ADC_ConvHalfCpltCallback(ADC_HandleTypeDef *hadc);    // 前半段就绪, DMA 搬运到前半段结束时自动调用。
    void HAL_ADC_ConvCpltCallback(ADC_HandleTypeDef *hadc);        // 后半段就绪, DMA 搬运到后半段结束时自动调用。
    ```
<br>
- #### CubeMX 配置要点
  - **启用 DMA 中断**：在 DMA 配置页面，勾选 **NVIC Settings** 下的 DMA 中断。
  - **保持循环模式**：DMA Mode 必须设置为 **Circular**。
  - 其余配置（ADC 连续转换、扫描模式、DMA Continuous Requests 等）保持不变，与单缓冲完全一致。
<br>
- #### 注意事项
  - DMA 缓冲区长度必须是 **每个子缓冲区长度的 2 倍**，如`HAL_ADC_Start_DMA(hadc, pData, Length) # Length = 两个子缓冲区的总长度`
  - **单个子缓冲区长度**需根据处理时间反推：子缓冲区被填满的时间应 **≥ CPU 完成上一轮数据处理所需的时间**，否则双缓冲也会丢数据。
  -  **中断中不要做耗时操作**：回调函数里只设标志位，不进行滤波、浮点运算等。
   - **数据一致性**：主循环处理子缓冲区时，DMA 正在写入另一半，CPU 不会碰到被覆盖的数据。
  - **缓冲区大小**：必须是偶数，否则半传输中断不会触发。
  - **避免手动停止 DMA**：在连续采集中调用 `HAL_ADC_Stop_DMA()` 会破坏双缓冲时序，保持循环模式一直运行。   
<br>
- #### 示例代码
	```c
	#define SAMPLES_PER_CH   200      // 每个通道的样本数
	#define CHANNEL_COUNT    3        // 通道数
	#define SUB_BUF_SIZE     (SAMPLES_PER_CH * CHANNEL_COUNT)
	#define DMA_BUF_SIZE     (SUB_BUF_SIZE * 2)
	
	volatile uint16_t adc_raw[DMA_BUF_SIZE];  // 总缓冲区（双倍）
	volatile uint16_t *ready_buf = NULL;      // 指向已就绪的子缓冲区
	volatile uint16_t ready_len = 0;          // 已就绪数据的长度
	
	// 前半段就绪（Ping 满了）
	void HAL_ADC_ConvHalfCpltCallback(ADC_HandleTypeDef *hadc)
	{
	    if (hadc->Instance == ADC1) {
	        ready_buf = &adc_raw[0];                    // 前半段起始地址
	        ready_len = SUB_BUF_SIZE;                   // 前半段数据长度
	        // 这里只做标记，复杂处理交给主循环
	    }
	}
	
	// 后半段就绪（Pong 满了）
	void HAL_ADC_ConvCpltCallback(ADC_HandleTypeDef *hadc)
	{
	    if (hadc->Instance == ADC1) {
	        ready_buf = &adc_raw[SUB_BUF_SIZE];         // 后半段起始地址
	        ready_len = SUB_BUF_SIZE;                   // 后半段数据长度
	        // 同样只做标记
	    }
	}
	
	// 主循环中安全处理
	void ProcessData(void)
	{
	    if (ready_buf != NULL) {
	        for (int ch = 0; ch < CHANNEL_COUNT; ch++) {
	            float sum = 0.0f;
	            for (int i = 0; i < SAMPLES_PER_CH; i++) {
	                sum += ready_buf[i * CHANNEL_COUNT + ch];
	            }
	            float avg_voltage = (sum / SAMPLES_PER_CH) * vdda_real / 4095.0f;
	            // 使用 avg_voltage...
	        }
	        ready_buf = NULL;  // 处理完成后清除标志
	    }
	}
	
	// 启动
	HAL_ADC_Start_DMA(&hadc1, (uint32_t *)adc_raw, DMA_BUF_SIZE);
	```
