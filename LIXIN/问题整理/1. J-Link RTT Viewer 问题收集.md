# 一、 J-Link RTT Viewer 中文乱码

## 问题现象

- 在 J-Link RTT Viewer 中查看目标板日志，中文显示为乱码

---

## 问题原因
-  RTT Viewer 本身不支持中文编码，用英文的则不会有问题

---

##  解决方案
- 改用终端 + `telnet` 连接 J-Link RTT 服务器去显示

---

## 具体步骤

### 1. 启动 J-Link GDB Server 或 JLinkExe（已配置好 RTT）

```bash
JLinkExe -device STM32F411CE -if SWD -speed 4000
```

**or**

```bash
JLinkExe -device STM32F411CE -if SWD -speed auto
```

> 连接后会自动启动 RTT Telnet 服务（端口 19021）。

在 `J-Link>` 提示符下执行：

```text
connect
```


### 2. 通过 telnet 连接 RTT 查看输出

```bash
telnet localhost 19021
```

# 二、`SEGGER_RTT_printf`函数漏打印

## 问题现象

- 在 J-Link RTT Viewer 中查看目标板日志，发现跳转到App之前的部分打印未显示出来
---

## 问题原因

-  跳转 App 之前 STM32 写入了 RTT 缓冲区，但 J-Link 还没来得及轮询读走，程序就跳转到 App 了。
- App 启动后 RTT 缓冲区被覆盖或者 RTT 控制块地址变了，那条日志永远丢失。

---

##  解决方案
- 在跳转前增加一个小的延时或者检查缓冲区是否为空，给 J-Link 足够时间读走缓冲区

```c
SEGGER_RTT_printf(0, "App jump start, addr=0x%08X\r\n", ApplicationAddress);
while (SEGGER_RTT_GetBytesInBuffer(0) > 0) { HAL_Delay(10); } // HAL_Delay(100); // 100ms 足够 J-Link 读走
jump_to_app(ApplicationAddress);
```

# 三、知识补充
## **使用`sz`命令发送app文件去开发版**

### 1. 准备工作

- 安装工具：
  ```bash
  sudo pacman -S lrzsz
  ```

- 确认串口设备（通常为 `/dev/ttyUSB0`）：
  ```bash
  ls -l /dev/ttyUSB*
  ```

- 确保当前用户有串口权限：
  ```bash
  sudo usermod -a -G dialout $USER   # 需注销重新登录生效
  ```

- **目标板端准备**：
> 看到 `CCCCC...` 或 `Ready for Ymodem...` 表示等待传输。

### 2. 使用方法

#### 第一步`stty` 设置，明确关闭校验

```bash
stty -F /dev/ttyUSB0 115200 raw -echo cs8 -cstopb -parenb -parodd
```

关键参数：

```
cs8      → 8位数据位
-cstopb  → 1位停止位
-parenb  → 关闭奇偶校验  ← 这个最关键
-parodd  → 关闭奇校验
```

--- 

#### 第二步发送文件

```bash
sz -k --ymodem firmware.bin < /dev/ttyUSB0 > /dev/ttyUSB0
```

- `-k`选项，用于指示在文件传输完成后**保留（Keep）源文件**
- `--ymodem` 指定 Ymodem 协议。
- `< /dev/ttyUSB0 > /dev/ttyUSB0` 将标准输入输出重定向到串口，必须同时重定向。
