## 轮询模式
1. 发送函数：`HAL_StatusTypeDef HAL_UART_Transmit(UART_HandleTypeDef *huart, const uint8_t *pData, uint16_t Size, uint32_t Timeout)`
2. 接收函数：`HAL_StatusTypeDef HAL_UART_Receive(UART_HandleTypeDef *huart, uint8_t *pData, uint16_t Size, uint32_t Timeout)`
	![](file-20260505213915031.png)
	![](file-20260505213915034.png)
	轮询模式下的发送和接收函数都是阻塞运行的，即函数运行时CPU是不能去处理其他事情，直至运行完成或超时！
	STM32每个串口内部都有发送数据寄存器（TDR）和发送移位寄存器，接收数据寄存器（RDR）和接收移位寄存器。当我们调用发送函数时，CPU会将数据移动到发送数据寄存器，发送数据寄存器再将数据移动到发送移位寄存器，每个寄存器为8位即一个字节，而后发送移位寄存器便会按照我们设定的波特率将数据以锯齿波的形式从tx引脚发送出去；而发送数据寄存器会在发送移位寄存器中的数据发送完成后将数据移动到发送移位寄存器中继续发送，此时CPU会在发送数据寄存器为空时将下一个数据移动到发送数据寄存器中，不停的查询寄存器中的数据是否已经移走，直至全部数据发送完毕！接收数据函数的原理也是同理。

## DMA模式
**DMA-(Direct Memory Access), 故名思意就是直接从内存中搬运数据。可实现从变量（内存）（或外设）到外设（寄存器）（或变量）之间的数据搬运，目的是为了减轻CPU的负担，提升效率**

### HAL 库为什么要求同时开启 UART 中断？
当我们调用 `HAL_UART_Transmit_DMA` 时，HAL 内部会做两件事：

1. **启动 DMA**，让它自动把内存数据搬到 UART 的发送数据寄存器 (TDR)；
2. **设置 DMA 传输完成的中断回调**，当 DMA 把最后一个字节搬完后，进入 DMA 中断，注意此时移位寄存器还在将数据搬运到外设。

- DMA 把最后 1 个字节写入 TDR 时，UART 的移位寄存器可能还在往外移位，这个字节尚未完全通过 TX 线发出。
- STM32 的 UART 提供 **传输完成标志 (TC)**，当数据帧最后一位从移位寄存器输出后，硬件会置起 `TC` 标志，并可触发中断。
- **HAL 库为了保证所有数据确实从物理线路上发完**，在 DMA 传输完成的中断回调里，不会直接调用 `HAL_UART_TxCpltCallback`，而是**开启 UART 的 TC (传输完成) 中断**，然后退出。

DMA 中断结束后，系统等待 **USART 的 TC 中断**，在这个 TC 中断服务函数（`USART2_IRQHandler`）里，HAL 才会识别到发送真正结束，进而调用我们熟悉的 `HAL_UART_TxCpltCallback`。
**总结一句话：`HAL_UART_Transmit_DMA` 结束的回调链路是：DMA TC 中断 → 开启 UART TC 中断 → UART TC 中断 → `HAL_UART_TxCpltCallback`，缺了 UART 的 NVIC 中断就无法走完最后一步。**

## 串口不定长数据接收
[详细的参考文章](https://zhuanlan.zhihu.com/p/566271584)
### 核心机制：空闲中断（IDLE）
STM32 的 USART 外设有一个**空闲中断（IDLE）**。当串口线路上**连续一个字节时间内没有收到数据**，硬件就会置位这个中断标志。

- **一帧结束的标志**：发送方停止发送后，线路会保持高电平。当这个高电平持续超过一个字节的时间，硬件就认为“空闲”了。
- **打开串口空闲中断**：`__HAL_UART_ENABLE_IT(&huart1,UART_IT_IDLE);//打开串口空闲中断`
- **HAL 库的封装**：`HAL_UARTEx_ReceiveToIdle_xxx` 系列函数正是配合 DMA/中断，在检测到这个 IDLE 事件时调用回调函数，并告诉你“一共收到了多少个字节”。

### 三个函数
|函数|模式|典型用法|
|---|---|---|
|`HAL_UARTEx_ReceiveToIdle_DMA`|DMA + IDLE 中断|最常用，CPU 负担最小，适合中大流量|
|`HAL_UARTEx_ReceiveToIdle_IT`|中断 + IDLE 中断|每收到一个字节都进一次中断，适合小流量|
|`HAL_UARTEx_ReceiveToIdle`|阻塞 + IDLE|一直等到 IDLE 或超时才返回，会卡死CPU|

**参数说明**

- `huart`：串口句柄。
    
- `pData`：接收缓冲区指针。
    
- `Size`：缓冲区的**最大容量**（能接收的最多字节数）。注意不是实际接收长度。
    
- `RxLen`（仅阻塞模式）：指向一个变量的指针，函数返回后**存放本次实际收到的字节数**。

### 统一回调函数
无论你用的是 DMA 模式还是中断模式，最终都会进入这个回调函数：
```c fold
void HAL_UARTEx_RxEventCallback(UART_HandleTypeDef *huart, uint16_t Size)
{
    // Size 是本次实际收到的数据长度
    if (huart->Instance == USART2) {
        // 在这里处理刚收到的数据
        // 数据存放在你传入的缓冲区里，有效长度为 Size
    }
	printf(666);
    // 处理完后，需要重新开启接收，等待下一帧
    HAL_UARTEx_ReceiveToIdle_DMA(&huart2, rx_buf, RX_BUF_MAX_SIZE);
}
```
**注意**：在 HAL 库中，这个函数被声明为 `__weak`，你需要在 `main.c` 或其他源文件中自己重写它。  
`Size` 参数就是**本次实际接收到的字节数**，这是不定长接收的核心。

### 接收过半中断

当使用 DMA 搬运数据时，DMA 本身有两个中断：

1. **传输完成中断（TC）**：数据搬完 `Size` 个了，触发回调。
2. **半传输中断（HT）**：数据搬完 `Size / 2` 个了，也会触发回调。

如果你用 `HAL_UARTEx_ReceiveToIdle_DMA`，半传输中断会**意外触发** `HAL_UARTEx_RxEventCallback`，导致你误以为已经收到新数据。

解决办法：在初始化完 DMA 后，**关闭 DMA 的半传输中断**。
```c
__HAL_DMA_DISABLE_IT(&hdma_usart1_rx, DMA_IT_HT);
```


**解释**：如果不关，当你收到的数据量**恰好达到缓冲区一半**时，会先因为 HT 事件进一次回调（Size = 缓冲区一半长度），过一会儿又因为 IDLE 事件再进一次回调（Size = 实际长度）。你的业务逻辑会混乱。  虽然最新版 HAL 库（1.11.x 以后）已经内部处理了 HT 不再重复调用，但在 F4 的旧 HAL 版本中，关掉 HT 仍然是最稳妥的做法。
