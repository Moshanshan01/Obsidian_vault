# 中断流程如下：
您说得对，我上一轮的补充侧重了EXTI外设层，但在笔记正文中确实遗漏了NVIC层的**ISER/ICER寄存器**描述。它们是中断能否最终送达CPU的关键使能开关。

以下是将ISER/ICER明确补入您笔记流程的完整版本，层级关系更加清晰：

---

### 📓 **STM32 EXTI 中断寄存器链路完整笔记（修正版）**

> **1. 配置与屏蔽 (EXTI层与NVIC层)**
> - **外设层 (EXTI)**：以 PA0 为例，当 PA0 被配置为中断输入时，**EXTI 中断屏蔽寄存器 (IMR)** 的第 0 位会被置 1。若为 PA1，则第 1 位被置 1。
> - **内核层 (NVIC)**：同时，必须在 NVIC 中使能对应的中断通道。此时，软件会操作 **NVIC 中断使能置位寄存器 (ISER)** 的对应位（写1），相当于打开了 NVIC 内部的大门。若需关闭此中断，则写 **NVIC 中断清除使能寄存器 (ICER)** 对应位。
> - 🔄 **补充：区分中断与事件**：如果仅需触发内部事件（如 ADC 采样）而不产生 CPU 中断，则应将 **事件屏蔽寄存器 (EMR)** 的对应位置 1。*注：IMR 与 EMR 互斥使用，信号流走向不同（IMR 通向 NVIC，EMR 通向其他外设的触发输入端）。*
> _⚠️ **特别注意**：PAx、PBx、PCx... 所有端口号相同的引脚（例如 PA0、PB0、PC0）**共用**同一条内部中断触发线路（EXTI0）。因此，**在同一时刻，通常只能开启其中一个引脚的 EXTI 中断功能**，否则多个引脚的电平变化会互相干扰，导致逻辑混乱。_

> **2. 触发检测与挂起 (EXTI层)**
> - 设置触发条件：若将 PA0 设置为下降沿触发，则**下降沿触发选择寄存器 (FTSR)** 的第 0 位被置 1。
> - 🔄 **补充上升沿配置**：若设置为上升沿触发，则对应操作 **上升沿触发选择寄存器 (RTSR)** 的第 0 位。若双边沿触发，则 RTSR 和 FTSR 对应位**同时置 1**。
> - 当外部引脚 PA0 产生下降沿电信号时，信号进入**边沿检测电路**。
> - 检测到符合条件的边沿后，硬件会将 **EXTI 的请求挂起寄存器 (PR)** 的第 0 位**自动置 1**。
> _⚠️ **注意**：此处的“挂起寄存器”属于 **EXTI 外设层**，用于记录“是哪个引脚触发了请求”。_

> **3. 向内核上报 (NVIC介入与仲裁)**
> - **信号传递条件**：只有当 **EXTI_PR** 位为 1，且 **EXTI_IMR** 对应位为 1，且 **NVIC_ISER** 对应位为 1 时，中断请求信号才会被送达 CPU 内核。
> - **NVIC挂起**：信号到达 NVIC 后，硬件会自动将 **NVIC 中断挂起寄存器 (ISPR)** 的对应位置 1。此时中断处于“已请求、待响应”状态。
> - **CPU响应**：CPU 根据当前优先级与中断优先级进行比较，若决定响应，则**硬件自动清除 NVIC 的挂起位 (ISPR)**，并跳转执行对应的中断服务函数。对于 PA0，即进入 `EXTI0_IRQHandler`。
> - 🔄 **补充：软件清除 NVIC 挂起 (ICPR 的作用)**：
>    - 寄存器：**中断清除挂起寄存器 (ICPR)**。
>    - 作用：与 ISPR 相反，向 ICPR 的某位写 **1**，可以**手动清除**对应中断的 NVIC 挂起状态（即撤消一个尚未被 CPU 响应的中断请求）。
>    - 应用场景：在系统启动时，可能用于清除残留的挂起标志；或者在软件逻辑中，决定**主动丢弃**一个尚未处理的中断请求（例如超时后不再需要该中断）。

> **4. 中断结束与清理 (软件干预)**
> - **清理EXTI层**：进入中断服务函数后，**必须由软件显式地清除 EXTI 外设层的 PR 寄存器位**（写 1 清0）。
> - **死锁风险**：若不清除此位，当函数退出后，由于 EXTI_PR 仍为 1，会导致中断**反复重入**，造成程序死锁。
> - 🔄 **补充：软件触发中断**：在调试或特殊逻辑中，可通过向 **软件中断事件寄存器 (SWIER)** 的对应位写 1，来**模拟硬件触发**。此时同样会置起 PR 位，并引发后续中断流程（前提是 IMR 已开启）。
> _(补充：NVIC 层的 ISPR 挂起位通常在进入 ISR 时硬件自动清除，无需软件干预。)_

# 补充：
- ## **当同时发生两个中断时，CPU会怎么处理呢？**
	![](file-20260505213914989.png)
	在cubemx中，当我们将对应GPIO口设置为中断后，在System Core下的NVIC会看到所以中断的开关页面，在此页面我们可以设置不同中断的优先级，优先级可以分为两种，分别为抢占优先级（Preemption Priority）和响应优先级（Sub Priority），其中抢占优先级优先级最高，不同中断中抢占优先级的数值越小的优先级越高；但两个中断同时触发时，抢占优先级数值小的先执行，但当抢占优先级大小相同时，则看响应优先级，同样的越小越先执行！当一个中断正在执行，另外一个抢占优先级更高而非响应优先级更高的中断则会打断当前正在执行的中断，优先执行自己，当自己执行完成后才会回去执行之前的中断！
	优先级由四位二进制设置，可通过上图的左上角位置设置优先级的位分配，cubemx默认时抢占优先级占据全部位。
<br>
- ## **什么是写1清0（Write-1-to-Clear）**
> 现在 **PA0（第 0 位）** 和 **PA1（第 1 位）** 同时触发了中断，PR 寄存器的值是 `0x00000003`（二进制 `...0011`）。  
> 中断服务函数是处理 PA0 的，你只想清除第 0 位，保留第 1 位等会儿处理。
> 
> **如果是“写 0 清 0”**：  
>   你需要执行的代码逻辑是：`PR = PR & ~(1<<0);`（读出现值 `0x03`，把第 0 位改成 0，得到 `0x02`，写回去）。  
>   **风险来了**：就在你 **读出** `0x03` 之后、**写回** `0x02` 之前的这一瞬间，**PA2（第 2 位）** 恰好触发了中断。硬件瞬间把 PR 的第 2 位置 1，PR 变成了 `0x07`。  
>   紧接着，你的软件执行写回操作，把 `0x02` 强行覆盖进去。  
>   **结果**：PA1 的挂起位还在（符合预期），但 **PA2 刚刚产生的中断标志被你硬生生抹掉了**！这个中断就丢了。
>   
> **如果是“写 1 清 0”**：  
>   你只需要执行：`PR = (1<<0);`（往第 0 位写 1，其他位写 0）。  
>   **硬件行为**：只有你写了 1 的那个位（第 0 位）会被硬件电路复位。**对于你写 0 的其他位（第 1 位、第 2 位），硬件完全不予理睬，保持原样。**  
>   **结果**：PA0 被清除，PA1 保持挂起，PA2 也保持挂起。完美。
>
>
> ** 硬件电路视角**
> 
> 在芯片内部，每个 PR 寄存器位对应一个 **SR 锁存器** 或 **D 触发器**。
> 
> - **置位端 (Set)**：连到边沿检测电路，有脉冲就置 1。
>     
> - **复位端 (Reset)**：连到一个 **“写 1 检测”** 电路。当软件往这个位写 1 时，复位端收到一个脉冲，将输出清 0。写 0 时，复位端没有脉冲，电路不动。
>     
> 
> 这就实现了 **“只修改我想改的位，其他位不受影响”** 的原子操作。
>
>
> HAL 库函数 `__HAL_GPIO_EXTI_CLEAR_IT(GPIO_PIN_0); \\GPIO_PIN_0 -> ((uint16_t)0x0001)`它的底层宏定义展开后就是这样:
> ```c
>#define __HAL_GPIO_EXTI_CLEAR_IT(__EXTI_LINE__) (EXTI->PR = (__EXTI_LINE__))
> ```
>它直接往 PR 寄存器里**写入对应位的掩码**，正是利用了 **“写 1 清 0”** 的机制
