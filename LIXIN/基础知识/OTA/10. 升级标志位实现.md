# 升级标志位实现

> OTA 流程的**入口触发机制**。App 写升级标志后复位，Bootloader 上电检查标志决定走升级流程还是直接启动 App。详见 [[1. OTA 固件升级完整流程|总览]]。

---

## Bootloader 启动流程

```
上电
  ↓
Bootloader 检查升级标志（RTC 备份寄存器 / Flash 参数区）
  │
  ├─ 有升级标志
  │     ↓
  │   清除升级标志
  │     ↓
  │   Ymodem_Receive() 接收固件
  │     │
  │     ├─ 传输成功
  │     │     ↓
  │     │   校验完整性（SHA256 + ECDSA 验签）
  │     │     │
  │     │     ├─ 校验通过 → 写入版本号，跳转 App
  │     │     └─ 校验失败 → 停留在 Bootloader（等待重试）
  │     │
  │     └─ 传输失败/超时 → 停留在 Bootloader（等待重试）
  │
  └─ 无升级标志 → 直接跳转 App
```

> ⚠️ **AN2557 的实现缺陷**：标志在接收固件**之前**就被清除了。如果传输中断（串口断开、超时），升级标志已丢，下次上电直接进旧 App。更健壮的做法是**校验全部通过后再清除标志**，这样失败后重新上电还能再进升级模式。

## 实现代码

**升级标志写入（App 里触发）：**

```c
// 写 RTC 备份寄存器，断电不丢失
HAL_RTCEx_BKUPWrite(&hrtc, RTC_BKP_DR0, 0xDEADBEEF);
HAL_NVIC_SystemReset();  // 复位，进入 Bootloader
```

**升级标志检查（Bootloader 里）：**

```c
if (HAL_RTCEx_BKUPRead(&hrtc, RTC_BKP_DR0) == 0xDEADBEEF) {
    HAL_RTCEx_BKUPWrite(&hrtc, RTC_BKP_DR0, 0x00000000);  // 清除标志
    Ymodem_Receive(buf);
}
// 改进：将清除操作移到 Ymodem_Receive 成功 + SHA256/ECDSA 校验通过之后
```

## 存储位置选择

| 位置 | 优点 | 缺点 |
|------|------|------|
| RTC 备份寄存器 | 读写简单，不掉电不丢 | 完全掉电（VBAT 也没电）时丢失，升级请求被忽略 |
| Flash 参数区 | 真正掉电不丢 | 需要擦写 Flash，操作更重 |

> 如果设备 VBAT 始终有电（纽扣电池），RTC 备份寄存器足够。产品级建议用 Flash 参数区。
