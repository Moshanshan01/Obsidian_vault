# 哈希算法与完整性校验

> 在 OTA 流程中的位置：PC 端对 firmware.bin 算 SHA256 存入 [[8. 完整固件包格式设计|固件头]]，设备端解密后重新计算并比对，验证固件未被篡改。详见 [[1. OTA 固件升级完整流程|总览]] 第⑥⑦步。

---

## 一、什么是哈希

哈希函数是一种**单向压缩函数**，把任意长度的数据变成固定长度的摘要：

```
"hello"                    → MD5    → 5d41402abc4b2a76b9719d911017c592
"hello!"                   → MD5    → 6f1ed002ab5595859014ebf0951522d9
整个 100KB 的固件.bin       → MD5    → 某个 32 字符的字符串
```

关键特性：

```
1. 确定性：同样的输入永远产生同样的输出
2. 雪崩效应：改变输入的一个 bit，输出完全不同
3. 单向性：无法从摘要反推原始数据
4. 抗碰撞性：很难找到两个不同输入产生相同摘要
```

## 二、SHA256 VS MD5

MD5 已经被破解（可以人为构造碰撞），但在嵌入式里用于**完整性校验**还是够用的，不是用于安全认证。

更安全的场景用 **SHA256**：

```
MD5    → 128bit 摘要，速度快，完整性校验用
SHA256 → 256bit 摘要，速度稍慢，安全性更高，签名验证用

MD5现在的定位：
用于安全认证 → ❌ 绝对不能用
用于完整性校验（传输错误检测）→ ⚠️ 凑合，但建议换 SHA256
用于非安全场景（文件去重、缓存key）→ ✅ 没问题
```

## 三、MD5 原理

### MD5 输出 128bit（32个十六进制字符），处理过程：

**第一步：填充数据**

原始数据末尾填充，使长度满足 `length % 512 == 448`（bit为单位）：

```
原始数据: [data...]
填充后:   [data...][1][0000...0][原始长度64bit]
                    ↑           ↑
               强制填1       记录原始长度
总长度必须是 512bit 的整数倍
```

**第二步：初始化4个32bit寄存器**

```c
uint32_t A = 0x67452301;
uint32_t B = 0xEFCDAB89;
uint32_t C = 0x98BADCFE;
uint32_t D = 0x10325476;
```

这四个初始值是 MD5 标准规定的魔数。

**第三步：按512bit分组循环压缩**

每组 512bit 经过 64 轮运算，每轮用不同的非线性函数混合 A/B/C/D：

```c
// 四种非线性函数，每16轮换一个
F(B,C,D) = (B & C) | (~B & D)   // 轮1-16
G(B,C,D) = (B & D) | (C & ~D)   // 轮17-32
H(B,C,D) = B ^ C ^ D             // 轮33-48
I(B,C,D) = C ^ (B | ~D)          // 轮49-64
```

每轮运算：

```c
// 以第一轮为例
temp = B + left_rotate(A + F(B,C,D) + M[i] + T[i], s);
A = D; D = C; C = B; B = temp;
// M[i] = 当前数据块的第i个32bit字
// T[i] = sin函数生成的常数表
// s    = 循环左移位数
```

**第四步：输出**

所有分组处理完后，A/B/C/D 拼接输出 128bit 摘要。

### MD5 为什么不安全

**碰撞攻击**：2004 年王小云教授证明可以人为构造两个不同内容但 MD5 相同的文件：

```
文件A（正常固件）→ MD5 → abc123
文件B（恶意固件）→ MD5 → abc123  ← 可以人为构造！
```

攻击者可以构造一个和正版固件 MD5 相同的恶意固件，完整性校验无法发现。

**彩虹表攻击**：预先计算大量输入的 MD5，建成查找表，收到摘要直接查表还原。

> ⚠️ 彩虹表只对**短输入**（如密码，通常 < 20 字符）有效，对固件这种动辄几十上百 KB 的二进制完全不实用。这条放在这是讲 MD5 的通用弱点，不是说固件哈希会被彩虹表反推——固件场景下真正需要担心的是**碰撞攻击**（下面那条）。

## 四、SHA256 原理

**SHA256 的作用**：

整个固件接收完之后，对完整固件计算 SHA256，和固件头里的摘要对比，验证**固件整体没有被篡改；**

SHA256 输出 256bit（64个十六进制字符），和 MD5 整体流程类似但更复杂更安全。

**初始化8个32bit寄存器：**

```c
// 取自前8个素数平方根的小数部分
uint32_t h0 = 0x6a09e667;
uint32_t h1 = 0xbb67ae85;
uint32_t h2 = 0x3c6ef372;
uint32_t h3 = 0xa54ff53a;
uint32_t h4 = 0x510e527f;
uint32_t h5 = 0x9b05688c;
uint32_t h6 = 0x1f83d9ab;
uint32_t h7 = 0x5be0cd19;
```

**按512bit分组，每组64轮压缩：**

```c
// 每轮用到两个复杂的混合函数
uint32_t S1    = right_rotate(e,6) ^ right_rotate(e,11) ^ right_rotate(e,25);
uint32_t ch    = (e & f) ^ (~e & g);
uint32_t temp1 = h + S1 + ch + K[i] + W[i];

uint32_t S0    = right_rotate(a,2) ^ right_rotate(a,13) ^ right_rotate(a,22);
uint32_t maj   = (a & b) ^ (a & c) ^ (b & c);
uint32_t temp2 = S0 + maj;

// 更新8个寄存器
h=g; g=f; f=e; e=d+temp1;
d=c; c=b; b=a; a=temp1+temp2;
```

比 MD5 安全的根本原因：

- 输出更长（256bit vs 128bit），暴力破解难度指数级增加
- 更复杂的混合函数，抗碰撞性更强
- 目前没有已知的实用碰撞攻击
