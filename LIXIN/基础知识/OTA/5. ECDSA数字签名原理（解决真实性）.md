# ECDSA 数字签名原理（解决真实性）

> 在 OTA 流程中的位置：PC 端用 ECDSA 私钥对 SHA256 摘要签名，设备端用内置公钥验签，证明固件来自合法发布者。详见 [[1. OTA 固件升级完整流程|总览]] 第④⑤步。非对称加密在这里**只用于签名**（真实性），不用于加密固件（加密用的是 [[4. AES 原理（解决保密性）|AES]]）。

---

## 一、为什么需要非对称加密

AES 是对称加密，加解密用同一个密钥。这引出一个根本问题：

```
密钥必须提前烧进 STM32 才能解密固件
但密钥怎么安全地写进去？生产线、供应链任何一个环节泄露，加密就没意义了
```

这叫**密钥分发问题**。非对称加密用两把钥匙解决这个问题：

```
私钥（Private Key）— 只在开发者电脑/服务器上，绝对不出现在设备上
公钥（Public Key） — 编译时硬编码进 Bootloader，可以公开，无需保密
```

私钥签名 → 公钥验证。公钥即使被拿走，没有私钥也无法伪造签名。

## 二、ECC 和 ECDSA 的关系

> ⚠️ 这两个概念容易混淆，必须搞清楚：

```
ECC（Elliptic Curve Cryptography）
    椭圆曲线密码学，是一套数学基础。
    就像"大整数分解"是 RSA 的数学基础一样，
    ECC 是一类算法的数学基础，不是一个具体的算法。

ECDSA（Elliptic Curve Digital Signature Algorithm）
    椭圆曲线数字签名算法，是基于 ECC 数学的具体签名算法。
    我们 OTA 里用的就是 ECDSA，不是"ECC"。
```

类比：
```
RSA 数学基础（大整数分解）→ RSA 签名算法
ECC 数学基础（椭圆曲线）  → ECDSA 签名算法
```

## 三、RSA 签名原理

RSA 基于**大整数分解**难题：把两个大素数的乘积分解回两个素数极其困难。

**密钥生成：**
```
1. 选两个大素数 p、q
2. n = p × q
3. φ(n) = (p-1)(q-1)
4. 选 e，满足 1 < e < φ(n) 且 gcd(e, φ(n)) = 1
5. 求 d，满足 e×d ≡ 1 (mod φ(n))

公钥 = (n, e)
私钥 = (n, d)
```

**RSA 签名与验证：**
```
签名：signature = hash^d mod n    （私钥运算）

验证：recovered_hash = signature^e mod n  （公钥运算）
      检查 recovered_hash == 自己计算的 hash
```

**关键特性：RSA 验证时可以从签名中"解出"（recover）哈希值。**
验证函数只需要签名和公钥，不需要哈希值作为输入——因为哈希值可以从签名里解出来。

## 四、ECDSA 签名原理

ECDSA 基于**椭圆曲线离散对数**难题：已知点 P 和 kP，求 k 极其困难。

**椭圆曲线上的点运算：**
```
曲线方程：y² = x³ + ax + b (mod p)

点加法：两点 P、Q → 连线与曲线的第三个交点取反 = P+Q
点乘法：k × G = G + G + G ... (k次，G 是曲线基点)

私钥 d：一个大整数（随机选取）
公钥 Q：Q = d × G（点乘运算）
```

**ECDSA 签名过程（PC 端）：**
```
输入：hash（32字节）、私钥 d、随机数 k
1. 计算椭圆曲线点 R = k × G
2. r = R.x mod n       （取 R 的 x 坐标）
3. s = k⁻¹ × (hash + r×d) mod n
4. 输出签名 (r, s)
```

**ECDSA 验证过程（STM32 端）：**
```
输入：hash（32字节）、公钥 Q、签名 (r, s)
1. u1 = hash × s⁻¹ mod n
2. u2 = r × s⁻¹ mod n
3. 计算点 X = u1×G + u2×Q
4. 验证 X.x mod n == r
   等于 → 签名有效
   不等 → 签名无效
```

## 五、⭐ RSA vs ECDSA 最关键的区别（影响代码写法）

这个区别直接决定了你的代码怎么写，不理解这个必然写出错误的代码：

| | RSA 验证 | ECDSA 验证 |
|--|---------|-----------|
| **哈希的角色** | 哈希是**输出**，从签名里解密出来 | 哈希是**输入**，必须自己先算好再传进去 |
| **验证函数输入** | 只需要签名 + 公钥 | 需要签名 + 公钥 + **哈希值** |
| **验证函数输出** | 解出哈希值，再比对 | 直接返回 true/false |
| **数学本质** | 解密操作（逆运算） | 椭圆曲线点验证（无法逆推） |

**用伪代码表示：**

```
RSA 验证：
  recovered_hash = rsa_verify(signature, public_key)  // 哈希是输出
  return recovered_hash == sha256(firmware)

ECDSA 验证：
  my_hash = sha256(firmware)                           // 必须先自己算
  return ecdsa_verify(signature, public_key, my_hash) // 哈希是输入
```

**对应到 mbedTLS 代码：**

```c
// RSA 验证风格（哈希从签名里解出来）
mbedtls_rsa_pkcs1_verify(&rsa, MBEDTLS_MD_SHA256,
    32, hash,      // ← hash 是用来"比对"的，不是运算输入
    signature);

// ECDSA 验证（hash 是必须的运算输入）
mbedtls_ecdsa_read_signature(&ecdsa,
    digest, 32,    // ← 这里的 digest 是 ECDSA 数学运算的直接输入
    signature, sig_len);
// 如果不传 digest，ECDSA 根本无法完成验证计算！
```

**为什么会走弯路：**
很多人按 RSA 的思维理解 ECDSA，以为验证函数会"从签名里解出哈希然后比对"，
结果以为 `digest` 参数只是用来"比对"的，或者对传入什么值无所谓。
实际上 ECDSA 的数学中 hash 是 u1/u2 计算的直接参数，传错了验证结果就是错的。

## 六、OTA 中的完整签名验证流程

### PC 端签名（打包时）

```
firmware.bin （原始固件）
     ↓
SHA256(firmware.bin) = digest（32字节）
     ↓
ECDSA.sign(digest, private_key) = signature（64字节 r+s）
     ↓
signature 存入固件头的 signature[64] 字段
```

### STM32 端验签（Bootloader 里）

```
收到固件包
     ↓
AES-CBC 解密 → firmware_plaintext
     ↓
SHA256(firmware_plaintext[0..firmware_size]) = my_digest  ← 自己算
     ↓
比对 my_digest == header->sha256                          ← 完整性验证
     ↓
ECDSA.verify(header->signature, public_key, my_digest)   ← my_digest 作为输入
     ↓
通过 → 固件可信，写 Flash
失败 → 拒绝
```

**关键：STM32 必须先自己算出 SHA256，再把它传给 ECDSA 验证函数。**
这和 RSA "从签名解出哈希再比对" 的流程是不一样的。

## 七、为什么选 ECDSA 而不是 RSA

```
256bit ECDSA ≈ 3072bit RSA 的安全强度

对比项          ECDSA-P256        RSA-2048/3072
密钥大小        32字节私钥         256/384字节私钥
签名大小        64字节(r+s)        256/384字节
验证速度        快                 慢（大数幂运算）
Flash占用       小（存公钥65字节） 大（存公钥256字节+）
嵌入式适合度    ✅ 非常适合         ⚠️ 勉强可用
```

## 八、SECP256R1 曲线参数

OTA 场景用的是 `SECP256R1`（也叫 P-256 或 prime256v1），是 NIST 推荐的 256 位曲线，mbedTLS 和 OpenSSL 都原生支持。

```c
// mbedTLS 中指定使用这条曲线
mbedtls_ecp_group_load(&ecdsa.grp, MBEDTLS_ECP_DP_SECP256R1);

// OpenSSL 中生成这条曲线的密钥对
openssl ecparam -genkey -name prime256v1 -out ec_private.pem
```
