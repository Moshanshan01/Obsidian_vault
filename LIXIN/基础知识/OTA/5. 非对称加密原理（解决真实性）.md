# 非对称加密与数字签名

> 在 OTA 流程中的位置：PC 端用 ECC 私钥对 SHA256 摘要签名，设备端用内置公钥验签，证明固件来自合法发布者。详见 [[1. OTA 固件升级完整流程|总览]] 第⑧步。注意非对称加密在这里**只用于签名**（真实性），不用于加密固件（加密用的是 [[4. AES 原理（解决保密性）|AES]]）。

---

## 为什么需要非对称加密

AES 是对称加密，加解密用同一个密钥。问题是：

```
密钥怎么安全地传给设备？
如果密钥在传输过程中被截获，加密就没意义了
```

这叫**密钥分发问题**，非对称加密解决这个问题。

## RSA 原理

RSA 基于一个数学难题：**大整数分解**。

把两个大素数相乘很容易，但把乘积分解回两个素数极其困难：

```
p = 61,  q = 53           → p × q = 3233    （容易）
已知 3233，求 p 和 q      →  很难
```

实际 RSA 用的是 2048bit 的大素数，分解需要宇宙年龄级别的时间。

**密钥生成：**

```
1. 选两个大素数 p、q
2. n = p × q
3. φ(n) = (p-1)(q-1)
4. 选 e，满足 1 < e < φ(n) 且 gcd(e, φ(n)) = 1
5. 求 d，满足 e×d ≡ 1 (mod φ(n))

公钥 = (n, e)
私钥 = (n, d)
```

**加密和解密：**

```
加密：密文 = 明文^e mod n  （用公钥）
解密：明文 = 密文^d mod n  （用私钥）

数字签名：
签名 = 摘要^d mod n        （用私钥签）
验证：摘要 = 签名^e mod n  （用公钥验）
```

## ECC 椭圆曲线原理

RSA 密钥太长（2048bit），嵌入式资源有限，ECC 用更短的密钥达到同等安全性。

ECC 基于椭圆曲线上的点运算：

```
椭圆曲线方程：y² = x³ + ax + b (mod p)

点加法：曲线上两点 P、Q → 连线与曲线的第三个交点取反 = P+Q
点乘法：k × P = P + P + P ... (k次)
```

难题：已知 P 和 k×P，求 k 极其困难（椭圆曲线离散对数问题）。

```
256bit ECC ≈ 3072bit RSA 的安全强度
STM32 上用 ECC-P256，计算量远小于 RSA-2048
```

## 数字签名在 OTA 中的流程

签名和验证的整体流程见 [[1. OTA 固件升级完整流程|总览]]，这里只列出要点：

- **签名对象**：不是对整个固件签名（太慢），而是对固件的 SHA256 摘要（32字节）签名
- **私钥位置**：只在 PC/服务器端，永远不出现在设备上
- **公钥位置**：编译时硬编码在 Bootloader 中，不可更改
- 设备端验签通过 = 固件确实来自持有私钥的合法发布者
