## 基本概念

AES 是**分组对称加密**，每次处理 16 字节（128bit）的数据块，密钥长度 128/192/256bit。

对称的意思：**加密和解密用同一个密钥**。

## AES 内部结构

### AES 把 16 字节数据排列成 4×4 的矩阵（State）：

```
输入16字节: [b0 b1 b2 b3 b4 b5 b6 b7 b8 b9 ba bb bc bd be bf]

State矩阵:
┌────┬────┬────┬────┐
│ b0 │ b4 │ b8 │ bc │
│ b1 │ b5 │ b9 │ bd │
│ b2 │ b6 │ ba │ be │
│ b3 │ b7 │ bb │ bf │
└────┴────┴────┴────┘
```

### AES-128 经过 **10轮**变换，前9轮每轮四个操作，**最后一轮不含 MixColumns**：

**SubBytes（字节替换）**：每个字节查 S-Box 表替换，引入非线性：

```
原字节 0x53 → 查S-Box → 0xed
```

S-Box 是一个预先计算好的 256 字节查找表，设计上保证没有线性关系。

**ShiftRows（行移位）**：每行循环左移不同位数：

```
行0: 不移动    [a0 a1 a2 a3] → [a0 a1 a2 a3]
行1: 左移1位   [b0 b1 b2 b3] → [b1 b2 b3 b0]
行2: 左移2位   [c0 c1 c2 c3] → [c2 c3 c0 c1]
行3: 左移3位   [d0 d1 d2 d3] → [d3 d0 d1 d2]
```

**MixColumns（列混合）**：每列做矩阵乘法，混合列内字节：

```c
// 在 GF(2^8) 有限域上做矩阵乘法
// 确保每个输出字节依赖所有输入字节
new_col = Matrix * old_col  (GF(2^8)运算)
```

**AddRoundKey（轮密钥加）**：State 与本轮子密钥做异或：

```
State[i][j] ^= RoundKey[i][j]
```

10 轮变换后输出 16 字节密文，原始数据被彻底打乱。

> ⚠️ **最后一轮没有 MixColumns**：第10轮只做 SubBytes → ShiftRows → AddRoundKey。如果自己实现 AES，忘了跳过最后一轮的 MixColumns 会解不出正确结果。

## CBC 模式原理

单独的 AES 每次加密 16 字节，相同明文产生相同密文，有规律可循。CBC 模式解决这个问题：

```
加密过程：
  密文1 = AES(明文1 XOR IV)
  密文2 = AES(明文2 XOR 密文1)
  密文3 = AES(明文3 XOR 密文2)

解密过程：
  明文1 = AES解密(密文1) XOR IV
  明文2 = AES解密(密文2) XOR 密文1
  明文3 = AES解密(密文3) XOR 密文2
```

IV（初始向量）是一个随机的 16 字节值，每次加密用不同的 IV，保证相同明文产生不同密文。

**IV 需要和密文一起发送**，接收方解密时需要用到，但 IV 本身不需要保密，可以明文传输。

## PKCS7 填充

AES 要求数据必须是 16 字节的整数倍，不足时需要填充()：

```
原始数据: [d1 d2 d3 d4 d5 d6 d7 d8 d9 da db]  11字节
需要填充: 16 - 11 = 5 字节
填充后:   [d1 d2 d3 d4 d5 d6 d7 d8 d9 da db 05 05 05 05 05]
                                              ↑  填充字节的值 = 填充的字节数
```

解密后检查最后一个字节的值，去掉对应数量的填充字节。

> ==⚠️注意==：
> - 无论原始数据长度是否是块大小的整数倍，PKCS#7 填充**总会存在**（除非手动关闭）。
> - 当数据长度正好是 16 字节的整数倍时，会追加一个完整的 16 字节块，每个字节的值都是 `0x10`（16）
> - 当数据长度不是 16 字节的整数倍时，当数据长度不是 16 字节的整数倍时，缺少几个字节就填充几个“几”。  
> 	填充值 = 16 - (数据长度 % 16)，填充数量 = 填充值。
