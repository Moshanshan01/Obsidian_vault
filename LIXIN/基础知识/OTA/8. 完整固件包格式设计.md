# 固件包格式设计

> 所有安全机制（加密、哈希、签名、版本控制）最终都落地为一个固件包格式。Bootloader 收到这个包后按预定顺序解析和验证。

---
## 固件包结构总览

```
┌──────────────────────────────────────────────────────┐
│  FirmwareHeader（128字节，明文不加密）                  │
│  ┌──────────┬────────┬─────────────┬──────────────┐  │
│  │ magic(4) │ ver(4) │ fw_size(4)  │   iv[16]     │  │
│  ├──────────┴────────┴─────────────┴──────────────┤  │
│  │                 sha256[32]                      │  │
│  ├─────────────────────────────────────────────────┤  │
│  │                signature[64]                    │  │
│  ├─────────────────────────────────────────────────┤  │
│  │              header_crc(4)                      │  │
│  └─────────────────────────────────────────────────┘  │
├──────────────────────────────────────────────────────┤
│  加密的固件数据（AES-CBC 密文，长度是16的整数倍）           │
└──────────────────────────────────────────────────────┘
```

---

## C 结构体定义

```c
typedef struct {
    uint8_t  magic[4];      // "FWPK" 魔数，标识这是固件包
    uint32_t version;       // 固件版本号，防降级
    uint32_t firmware_size; // 原始固件大小（PKCS7填充前），解密后SHA256用此长度
    uint8_t  iv[16];        // AES-CBC 的 IV
    uint8_t  sha256[32];    // 解密后固件的 SHA256
    uint8_t  signature[64]; // ECC-P256 对 SHA256 摘要的签名（r=32字节 + s=32字节）
    uint32_t header_crc;    // 头部自身的 CRC32，防头部损坏
} __attribute__((packed)) FirmwareHeader_t;

// sizeof(FirmwareHeader_t) = 4+4+4+16+32+64+4 = 128 字节，需在编译时断言验证：
// _Static_assert(sizeof(FirmwareHeader_t) == 128, "Header size mismatch");

// 完整固件包内存布局：
// [FirmwareHeader_t 128字节（明文）][AES-CBC 密文（长度是16的整数倍）]

// ⚠️ firmware_size 容易误解：
// 如果 firmware.bin 是 100000 字节，PKCS7 填充后变成 100016 字节再加密。
// header 里存的必须是原始的 100000，SHA256 也是对原始 100000 字节算的。
// 接收方解密后要先按 firmware_size 截断（去掉PKCS7填充），再做 SHA256。
```

---

## 头部为什么是明文不加密

头部**不加密**，明文传输，原因是 Bootloader 解密之前就需要用到头部字段，加密头部会陷入死循环：

```
要解密头部 → 需要 IV → IV 在头部里 → 需要先解密头部才能拿到 IV（矛盾）
```

头部各字段是否有保密需求：

| 字段 | 需要保密 | 原因 |
|------|---------|------|
| magic | 否 | 知道格式也无法伪造固件 |
| version | 否 | 无敏感信息 |
| firmware_size | 否 | 无敏感信息 |
| iv | 否 | IV 本来就不需要保密，每次随机生成保证密文不同 |
| sha256 | 否 | 单向哈希无法反推固件内容 |
| signature | 否 | 没有私钥无法伪造，公开也无妨 |
| header_crc | 否 | 无敏感信息 |

真正需要保密的固件内容在载荷区，那部分是加密的。

---

## 各字段说明

| 字段 | 大小 | 谁写入 | 用途 |
|------|------|--------|------|
| `magic` | 4B | PC打包脚本 | 快速识别固件包，防止把随机数据当固件处理 |
| `version` | 4B | PC打包脚本 | [[9. 固件验证流程实现\|防降级]]检查，只能升不能降 |
| `firmware_size` | 4B | PC打包脚本 | 解密后按此长度截断（去PKCS7填充），也是SHA256的输入长度 |
| `iv[16]` | 16B | PC打包脚本 | AES-CBC 解密的前置条件，PC 端每次随机生成 |
| `sha256[32]` | 32B | PC打包脚本 | 解密后固件的 [[3. 哈希算法（解决完整性）\|SHA256]]，用于完整性校验 |
| `signature[64]` | 64B | PC打包脚本 | 对 sha256 摘要的 [[5. ECDSA数字签名原理（解决真实性）\|ECDSA 签名]]，用于真实性验证（r=32字节 + s=32字节）|
| `header_crc` | 4B | PC打包脚本 | 头部自身的 CRC32，接收方先验证这个确保头部没损坏 |

---

## 验证顺序为什么是这个样子

设备端验证必须先从不需要解密的字段开始，逐步深入，越轻量的检查放越前面：

```
魔数 → 版本号 → 头部CRC → AES解密 → SHA256 → ECDSA验签
 ↑       ↑        ↑          ↑          ↑          ↑
轻量    轻量      轻量       重量        重量        重量
4字节  整数比较  整块CRC   遍历固件   遍历固件   椭圆曲线运算
```

如果把 AES 解密放最前面，一个损坏的固件包会白白浪费 CPU 时间做解密；
把 ECDSA 验签放最前面，任何人随便发个包就能让 STM32 做椭圆曲线运算，浪费资源。

## PC端打包脚本

PC 端打包用 Python 脚本自动完成整个流程，比手动敲 OpenSSL 命令可靠且可重复。

```python
#!/usr/bin/env python3
# pack_firmware.py
# 依赖：pip install pycryptodome
# 用法：python3 pack_firmware.py firmware.bin ec_private.pem output.pkg

import sys, struct, hashlib, os, subprocess, binascii
from Crypto.Cipher import AES
from Crypto.Util.Padding import pad

# ===== 配置（必须与 STM32 端 Bootloader 完全一致）=====
AES_KEY = bytes.fromhex("0123456789ABCDEF0123456789ABCDEF")  # 16字节密钥
FIRMWARE_VERSION = 3  # ❗ 每次发布必须递增，否则防降级检查会拒绝

def pack(bin_path, key_path, output_path):
    # 1. 读取原始固件
    with open(bin_path, "rb") as f:
        firmware = f.read()
    firmware_size = len(firmware)
    print(f"原始固件大小：{firmware_size} 字节")

    # 2. 计算 SHA256（对原始固件，PKCS7 填充之前）
    # ⚠️ 必须在填充和加密之前算，STM32 解密后截断再验证
    sha256 = hashlib.sha256(firmware).digest()
    print(f"SHA256：{sha256.hex()}")

    # 3. 随机生成 IV（每次打包不同，保证相同固件产生不同密文）
    iv = os.urandom(16)

    # 4. AES-CBC 加密（PKCS7 自动填充到16字节整数倍）
    cipher = AES.new(AES_KEY, AES.MODE_CBC, iv)
    ciphertext = cipher.encrypt(pad(firmware, 16))
    print(f"加密后大小：{len(ciphertext)} 字节（PKCS7填充后）")

    # 5. ECDSA 签名（对 SHA256 摘要签名，不是对整个固件签名）
    # OpenSSL 输出 DER 格式，这里截取前64字节存入头部
    # ⚠️ 生产环境建议用 python-ecdsa 库做正规 DER→raw(r+s) 格式转换
    subprocess.run([
        "openssl", "dgst", "-sha256",
        "-sign", key_path,
        "-out", "/tmp/fw.sig",
        bin_path
    ], check=True)
    with open("/tmp/fw.sig", "rb") as f:
        signature_der = f.read()
    signature = signature_der[:64].ljust(64, b'\x00')  # 截取/补齐到64字节

    # 6. 构造固件头（不含CRC部分）
    # 格式严格对应 C 结构体：
    # magic(4) + version(4) + firmware_size(4) + iv(16) + sha256(32) + signature(64) = 124字节
    header_without_crc = struct.pack(
        "<4sII16s32s64s",
        b"FWPK",           # magic[4]
        FIRMWARE_VERSION,  # version（uint32）
        firmware_size,     # firmware_size（原始大小，不是加密后大小）
        iv,                # iv[16]
        sha256,            # sha256[32]
        signature          # signature[64]
    )

    # 7. 计算头部 CRC32，拼接成完整128字节头部
    crc = binascii.crc32(header_without_crc) & 0xFFFFFFFF
    header = header_without_crc + struct.pack("<I", crc)
    assert len(header) == 128, f"头部大小错误：{len(header)}，应为128字节"

    # 8. 写出固件包：明文头部 + AES密文
    with open(output_path, "wb") as f:
        f.write(header)
        f.write(ciphertext)

    print(f"打包完成：{output_path}")
    print(f"固件包总大小：{len(header) + len(ciphertext)} 字节")
    print(f"版本号：{FIRMWARE_VERSION}")

if __name__ == "__main__":
    if len(sys.argv) != 4:
        print("用法：python3 pack_firmware.py firmware.bin ec_private.pem output.pkg")
        sys.exit(1)
    pack(sys.argv[1], sys.argv[2], sys.argv[3])
```

打包后用 Ymodem 发送固件包：

```bash
# 设置串口参数
stty -F /dev/ttyUSB0 115200 raw -echo cs8 -cstopb -parenb -parodd

# 发送固件包（不是裸 .bin，是打包后的 .pkg）
lrzsz-sz --ymodem output.pkg < /dev/ttyUSB0 > /dev/ttyUSB0
```
