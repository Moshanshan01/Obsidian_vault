
# 1. 基本定时器（使用内部时钟）
![](assets/7.%20定时器/file-20260324181634057.png)
![](assets/7.%20定时器/file-20260324165053724.png)
	**STM32 定时器通过 PSC 分频产生计数时钟，CNT 按该时钟计数至 ARR，溢出产生更新事件（UEV），并通过影子寄存器机制在更新事件时同步加载新参数，从而保证时序稳定。**	<br>
	1. **预分频器**（PSC）： 预分频器的作用是对定时器输入时钟（CK_PSC）进行分频，然后把分频后的时钟（CK_CNT）送给计数器。
		- PSC 寄存器是一个 16 位值，**实际分频系数 = PSC + 1**（范围 1～65536）。
		- PSC = 0 时 → 1 分频（时钟原封不动通过）。
		- PSC = 1 时 → 2 分频（每来 2 个脉冲，输出 1 个脉冲给计数器）。
		- PSC = 7199 时 → **7200 分频**。
		- 虽然我们写入的是 PSC 寄存器，但实际参与分频的是其影子寄存器。新写入的 PSC 值不会立即生效，而是需要等到更新事件（UEV）发生时才会被加载（PSC 的预装载功能无法关闭）。<br>  
	2. **计数器**（CNT）：计数器寄存器（TIMx_CNT）是一个向上（或向下）计数的寄存器。
		- 每接收到一个来自预分频器输出的计数时钟脉冲（CK_CNT），CNT 的值就 **+1**（向上计数模式）。
		- 当 CNT 的值达到 ARR 时，下一个 CK_CNT 脉冲到来时，CNT 才会从 ARR 跳回 0，同时产生更新事件（中断）。
		- 因此，一个完整周期 CNT 实际经历了 **ARR + 1** 个脉冲。<br>
	3. **自动重装载寄存器（ARR）工作原理（向上计数模式）**：
		- 当计数器 CNT **从 0 开始计数到 ARR** 时，**不会立即产生更新事件**。
		- 必须等到**下一次计数时钟脉冲**到来时，CNT 才会从 ARR **直接跳回 0**，同时产生更新事件（UIF 置 1，触发中断/DMA/等）。
		- 因此，一个完整的计数周期包含 **ARR + 1** 个计数脉冲（从 0 → 1 → … → ARR → 0）。
		- 如果你希望**正好计数 N 次**后触发一次更新中断，则必须设置 **ARR = N - 1**。
		- 自动重装载寄存器（ARR）同样具有影子寄存器机制（当使能预装载时）。新写入的 ARR 值不会立即作用于计数过程，而是在更新事件（UEV）发生时才会被加载，从而避免计数周期中途突变！新设置的 ARR 值是否立即生效取决于 ARPE 位（TIMx_CR1 寄存器）。
			- ARPE = 0：立即生效。
			- ARPE = 1：需要在下一个更新事件（UEV）时才加载到影子寄存器并生效（这是最常用的模式，可避免在计数过程中突然改变周期导致 glitch）。<br>
	4. **注意**：
		**更新事件（UEV） 不只来自溢出（下一周期来临）！**
		还可以来自：
			- 手动触发（UG 位）
			- 某些模式切换
			- 初始化时强制更新
## 函数
1.  **开启计时器**：`HAL_StatusTypeDef HAL_TIM_Base_Start(TIM_HandleTypeDef *htim)`
2.  **停止计时器**：`HAL_StatusTypeDef HAL_TIM_Base_Stop(TIM_HandleTypeDef *htim)`
3. **开启定时器+中断**：`HAL_StatusTypeDef HAL_TIM_Base_Start_IT(TIM_HandleTypeDef *htim)`
4. **停止定时器+中断**：`HAL_StatusTypeDef HAL_TIM_Base_Stop_IT(TIM_HandleTypeDef *htim)`
5. **开启定时器+DMA**：`HAL_StatusTypeDef HAL_TIM_Base_Start_DMA(TIM_HandleTypeDef *htim, const uint32_t *pData, uint16_t Length)`
6. **停止定时器+DMA**：`HAL_StatusTypeDef HAL_TIM_Base_Stop_DMA(TIM_HandleTypeDef *htim, const uint32_t *pData, uint16_t Length)`
7. **回调函数**：`void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)`
## 宏
1. **获取计数器的值**：`__HAL_TIM_GET_COUNTER(__HANDLE__)`
2. **设置计数器的值**：`__HAL_TIM_SET_COUNTER(__HANDLE__, __COUNTER__)`
3. **获取自动重装载寄存器的值**：`__HAL_TIM_GET_AUTORELOAD(__HANDLE__)`
4. **设置自动重装载寄存器的值**：`__HAL_TIM_SET_AUTORELOAD(__HANDLE__, __AUTORELOAD__)`
5. **设置预分频器的值**：`__HAL_TIM_SET_PRESCALER(__HANDLE__, __PRESC__)` 
6. **为了确保万无一失，建议在重新启动定时器之前，执行一套标准的“清理与重置”流程**:
	```c
	// 1. 先停止定时器 (确保状态可控) 
	HAL_TIM_Base_Stop(&htim1); 
	
	// 现象：假设你设定周期是 1000，定时器数到 500 时你把它停了。下次你再启动它，它会接着从 500 往上数，而不是从 0 开始
	// 2. 【关键】重置计数器，确保下次从 0 开始
	 __HAL_TIM_SET_COUNTER(&htim1, 0); 
	 
	 // 现象：如果停止时刚好产生过更新事件，或者之前的标志没清干净，后果便是当你再次启动定时器（特别是开启中断模式 `Start_IT`）时，CPU 会立刻响应一次中断，导致程序逻辑错乱。
	 // 3. 【关键】清除更新中断标志，防止一启动就误进中断 
	 __HAL_TIM_CLEAR_FLAG(&htim1, TIM_FLAG_UPDATE); 
	 
	 // 4. (可选) 如果你修改了 ARR 或 PSC，且需要立即生效 
	 // 强制产生一个更新事件，让新参数立即载入影子寄存器 
	 // 注意：这也会产生一个更新中断，所以通常要在清除标志位之后做
	  __HAL_TIM_GENERATE_SW_EVENT(&htim1, TIM_EVENTSOURCE_UPDATE); 
	  
	  // 5. 重新启动 
	  HAL_TIM_Base_Start(&htim1);  
	```

# 2. 外部时钟模式
**一句话理解：** 定时器默认用内部时钟（APB总线时钟）驱动计数器。**外部时钟模式**则让计数器随外部信号的每个边沿跳一次。
![](assets/7.%20定时器/file-20260402220924158.png)
![](assets/7.%20定时器/file-20260402224546448.png)![](assets/7.%20定时器/file-20260402223536526.png)
### 两种模式的区别

- **外部时钟模式2（ETR）**：通过专门的 **ETR引脚** 输入外部时钟信号，**不依赖从模式**。只需在CubeMX中将Clock Source选为“ETR2”，即可独立工作。这种模式下，从模式（Slave Mode）可以保持禁用。
- **外部时钟模式1**：通过 **输入捕获通道（TI1/2）** 输入外部时钟，**属于从模式的一种**（SMS寄存器设为`111`）。此时需要将从模式选为“External Clock Mode 1”。

> 大多数新手教程中讲的“外部时钟模式”默认指 **ETR（模式2）**，它**不是从模式的一部分**。而模式1才需要配置从模式。

| 外部时钟模式 1 | 外部时钟模式 2          |                 |
| -------- | ----------------- | --------------- |
| 信号引脚     | TI1 或 TI2（普通捕获引脚） | ETR（专用外部触发引脚）   |
| 寄存器设置    | SMS=111，TS 选择触发源  | ECE=1（SMCR 寄存器） |
| 适用场景     | 灵活，可配合滤波器         | 专为外部时钟设计，更直接    |
> 新手建议：优先用**模式2（ETR）**，配置更简单，CubeMX 里也只需勾选一项
### CubeMX 配置步骤（以模式2为例）

1. 打开目标定时器（如 TIM1），在 **Clock Source** 下拉选 **ETR2**
2. 引脚自动分配到 ETR 对应的 GPIO（如 PA12）
3. 在 **Configuration**中配置（可根据实际需要变动）：
	- `Counter Mode = Up` ✅ 向上计数
	- `Clock Polarity = non inverted` ✅ 上升沿计数
	- `Clock Filter = 0` ✅ 不滤波
	- `Clock Prescaler = Prescaler not used` ✅ 不分频
4. **Counter Settings**：
    - Period（ARR）：计满多少次触发一次溢出，按需填写
    - Counter Mode：Up（向上计数）即可
5. 生成代码

# 4. 输入捕获模式
![](assets/7.%20定时器/file-20260412175932798.png)
## 1. 什么是输入捕获
输入捕获（Input Capture，简称IC），当定时器通道输入引脚出现指定电平跳变（上升沿或下降沿）时，硬件会立即将当前计数器CNT的值“拍照”并锁存到对应的捕获/比较寄存器CCRx中。这一过程完全由硬件完成，不会受到程序执行延迟的影响，因此可用于精确测量外部信号的时间特性。
## 2. 哪些定时器可以使用此模式
每个高级定时器和通用定时器都拥有4个输入捕获通道，通用定时器和高级定时器的输入捕获电路没有区别

- **通用定时器**：TIM2、TIM3、TIM4、TIM5，均支持输入捕获
    
- **高级定时器**：TIM1、TIM8，同样支持输入捕获
    
- **基本定时器**：TIM6、TIM7，**不支持**输入捕获功能

## 3. 硬件工作原理（信号流向）
当外部信号进入STM32的引脚（如PA0，对应TIM2_CH1）时，信号会经过以下硬件路径：

**脚输入 → 输入滤波器 → 边沿检测器 → 信号选择器 → 预分频器 → 捕获事件（CCx事件）→ CCR寄存器锁存CNT值**

1. **GPIO引脚**：外部信号输入。
2. **输入滤波器**：数字滤波器，用于消除外部信号的高频毛刺（防抖）。可以设置采样频率和有效电平的连续采样次数。
3. **边沿检测器**：设置捕获触发条件（**上升沿**、**下降沿**或**双边沿**）。

4. **信号选择器**：每个通道可以通过直接模式或间接模式选择信号源：
	TI1和TI2是一对可以互相借用输入的通道，TI3和TI4同理。
	
	|模式|捕获通道|信号来源|用途|
	|---|---|---|---|
	|直接模式|CCR1|TI1FP1|周期/频率测量|
	|间接模式|CCR1|TI2FP1|测量高/低电平宽度|
	
4. **预分频器（IC Prescaler）**：每隔N个有效边沿才触发一次捕获（例如设置4，就是每4个上升沿捕获一次，常用于测超高频信号）。
5. **捕获/比较寄存器（CCR）**：当边沿到来时，硬件会瞬间将当前定时器的计数值（CNT）复制到对应的CCR寄存器中。
6. **中断标志位（CCxIF）**：捕获完成后，硬件自动将标志位置1，如果开启了中断，则触发CPU执行中断服务函数。

## 4. 核心寄存器
- **CNT (Counter Register)**：定时器的主计数器，根据时钟源不断累加。
- **CCR1 ~ CCR4 (Capture/Compare Register)**：捕获寄存器，**只读**（在输入捕获模式下），用于保存捕获瞬间的CNT值。
- **CCER (Capture/Compare Enable Register)**：控制捕获的极性（CCxP位），0=上升沿，1=下降沿。
- **CCMR1/2 (Capture/Compare Mode Register)**：配置通道映射（CCxS位设为01即输入模式）、滤波器参数、预分频参数。

	|寄存器|功能说明|
	|---|---|
	|TIMx_CR1|控制寄存器1，使能计数器等|
	|TIMx_PSC|预分频器，控制计数频率|
	|TIMx_ARR|自动重装载寄存器，决定溢出周期|
	|TIMx_CNT|计数器当前值|
	|TIMx_CCRx|捕获/比较寄存器，存储捕获到的CNT值|
	|TIMx_CCMR1/2|捕获/比较模式寄存器，配置输入滤波、边沿选择、分频等|
	|TIMx_CCER|捕获/比较使能寄存器，使能捕获通道、配置极性|
	|TIMx_DIER|DMA/中断使能寄存器，使能捕获中断|
	|TIMx_SR|状态寄存器，包含捕获标志位CCxIF|
## 5. 配置步骤
| 函数                                | 功能              |
| --------------------------------- | --------------- |
| `HAL_TIM_IC_Init()`               | 初始化定时器输入捕获      |
| `HAL_TIM_IC_ConfigChannel()`      | 配置输入捕获通道参数      |
| `HAL_TIM_IC_Start_IT()`           | 启动输入捕获（中断模式）    |
| `HAL_TIM_ReadCapturedValue()`     | 读取捕获到的CNT值      |
| `HAL_TIM_IC_CaptureCallback()`    | 输入捕获中断回调        |
| `HAL_TIM_PeriodElapsedCallback()` | 定时器更新中断回调（处理溢出） |
| `__HAL_TIM_SET_CAPTUREPOLARITY()` | 动态切换捕获边沿极性      |
无论是用标准库还是HAL库，底层逻辑是一致的：

1. **开启时钟**：开启GPIO和对应TIM的时钟。
2. **配置GPIO**：将引脚配置为复用推挽输出（AF），或者浮空输入（具体看芯片手册推荐）。
3. **配置时基**：
    - 设置预分频器（PSC），决定计数频率（例如72M时钟，PSC=71，则计数频率为1MHz，即1us计一个数）。
    - 设置自动重装载值（ARR），通常设为最大值（如0xFFFF），防止在测低频时计数器频繁溢出。
4. **配置输入捕获通道**：
    - 选择通道（如TIM_CHANNEL_1）。
    - 设置极性（上升沿/下降沿）。
    - 设置分频系数（通常不分频，即ICPrescaler=0）。
    - 设置滤波器（根据信号质量，通常0x0F左右即可）。
5. **配置从模式（如测脉宽）**：设置触发源和复位模式。
6. **开启中断**：在NVIC中配置捕获中断，并编写回调函数（如 `HAL_TIM_IC_CaptureCallback`）
# 5. 输出比较模式
![](assets/7.%20定时器/file-20260412212015508.png)
## 1. 什么是输出比较
输出比较（Output Compare，简称OC），当定时器的计数器CNT的值与预先设定的捕获/比较寄存器CCRx的值相等时，硬件会根据配置自动执行相应的动作——可以是设置引脚电平、翻转电平，或者产生中断/DMA请求。这一过程完全由硬件完成，可用于精确控制输出波形的时间特性。
## 2. 哪些定时器可以使用此模式
**同输入捕获**
## 3. 输出比较 vs 输入捕获
同一个定时器中，输出比较和输入捕获共用CCR寄存器和CH1~CH4通道引脚，因此**只能二选一使用**。

|维度|输出比较（OC）|输入捕获（IC）|
|---|---|---|
|引脚方向|输出端口（MCU输出信号）|输入端口（外部信号进入）|
|触发条件|CNT 值达到 CCR 设定值|外部引脚电平跳变|
|执行动作|改变引脚输出电平/产生中断|将 CNT 值锁存到 CCR|
|典型用途|生成PWM、方波、控制脉冲|测量频率、占空比、脉宽|

## 4. ## 硬件工作原理（信号流向）
输出比较通道的信号处理流程如下：
**CNT计数器与CCRx比较 → 输出模式控制器（生成OCxREF参考信号）→ 极性选择 → 输出使能 → 引脚输**

- **时基单元**：时钟触发 `CNT` 不断累加（或递减）。
- **比较器**：硬件实时对比 `CNT` 和 `CCRx` 的值。
- **输出比较控制器（OCREF）**：根据比较结果和配置的模式，生成一个内部参考信号 `OCREF`（高电平、低电平或翻转）。**注意：此时还没有输出到引脚！**
- **极性选择器（输出极性）**：可以对 `OCREF` 信号进行反转（高变低，低变高）。
- **输出使能**：只有使能了（CCER寄存器控制），信号才能通向引脚。
- **GPIO引脚**：最终体现为物理电平的变化（必须配置为复用推挽输出 AF_PP）。

## 5. 核心寄存器

|寄存器|功能说明|
|---|---|
|TIMx_CR1|控制寄存器1，包含计数器使能位CEN、计数方向DIR等|
|TIMx_PSC|预分频器，控制计数频率|
|TIMx_ARR|自动重装载寄存器，决定PWM周期（ARR越大，周期越长）|
|TIMx_CNT|不断变化的当前计数值|
|TIMx_CCRx|捕获/比较值寄存器。**可读可写**，在运行中修改它，下一次比较时立即生效（或通过预装载生效）（在PWM中决定占空比）|
|TIMx_CCMR1/2|捕获/比较模式寄存器，配置输出比较模式OCxM（决定比较匹配时发生什么动作）、预装载OCxPE、快速模式OCxFE等|
|TIMx_CCER|捕获/比较使能寄存器，使能输出通道CCxE、配置极性CCxP|
|TIMx_DIER|DMA/中断使能寄存器，使能比较中断CCxIE|
|TIMx_SR|状态寄存器，包含比较标志位CCxIF|
|TIMx_BDTR|断路和死区寄存器（仅高级定时器），配置死区时间和刹车功能|

## 6. 输出比较的八种模式
输出比较共有8种工作模式，通过TIMx_CCMRx寄存器中的OCxM[2:0]位配置：

| OCxM值 | 模式名称       | 匹配时 (CNT == CCR) 的动作         | 典型用途            |
| :---- | :--------- | :--------------------------- | :-------------- |
| `000` | 冻结         | OCREF保持当前状态不变                | 极少用，相当于暂停输出     |
| `001` | 匹配时置有效电平   | OCREF 强制拉高（有效）               | 产生单脉冲           |
| `010` | 匹配时置无效电平   | OCREF 强制拉低（无效）               | 产生单脉冲           |
| `011` | 翻转         | OCREF 电平反转（高变低，低变高）          | **生成50%占空比的方波** |
| `100` | 强制为无效电平    | 无视CNT，直接拉低OCREF              | 软件强行控制引脚电平      |
| `101` | 强制为有效电平    | 无视CNT，直接拉高OCREF              | 软件强行控制引脚电平      |
| `110` | **PWM模式1** | CNT < CCR 时有效，CNT >= CCR 时无效 | **最常用：生成PWM波**  |
| `111` | **PWM模式2** | CNT < CCR 时无效，CNT >= CCR 时有效 | 与PWM模式1完全相反     |
- **冻结模式**：比较匹配时无任何操作，用于暂时“冻结”PWM输出，保持当前电平不变。

- **匹配时置有效/无效电平**：在CNT达到CCR的瞬间改变电平，用于生成单脉冲或特定时刻的电平变化。

- **翻转模式**：每次匹配时电平翻转，可以输出频率可调、占空比始终为50%的PWM波形。输出波形的频率 = 定时器更新频率 / 2。

- **强制模式**：不依赖于CNT与CCR的比较，直接通过软件强制控制输出引脚的状态，无论计数器和比较寄存器如何。

- **PWM模式1/2**：向上计数时：
	PWM1：CNT < CCR 输出有效电平，CNT ≥ CCR 输出无效电平
	PWM2：CNT < CCR 输出无效电平，CNT ≥ CCR 输出有效电平

## 8. 配置步骤（以生成PWM为例）
- **开启时钟**：开启GPIO和对应TIM的时钟。
- **配置GPIO**：配置为**复用推挽输出（AF_PP）**，不要配置为普通的推挽输出，因为引脚电平是由定时器硬件接管（复用功能）的。
- **配置时基**：
    - 设置预分频（PSC）和重装载值（ARR），决定PWM的基础频率。
- **配置输出比较通道（OC）**：
    - 选择通道（如TIM_CHANNEL_1）。
    - 设置模式为 PWM模式1（或PWM模式2）。
    - 设置极性：通常设为 Low（因为硬件默认高电平有效，设为Low相当于将最终输出再反转一次，符合很多外设低电平有效的逻辑）。
    - 设置初始比较值（Pulse，即CCR的值，决定初始占空比）。
    - **开启预装载**：通常在HAL库中勾选 `CH Preload Enable`。
- **启动定时器**：`HAL_TIM_PWM_Start(&htimx, TIM_CHANNEL_x)`。
- **动态调节**：在运行中直接修改 `__HAL_TIM_SET_COMPARE(&htimx, TIM_CHANNEL_1, New_CCR_Value)` 即可平滑改变占空比
### 8.1 CubeMX配置
- **时钟配置**：选择合适的PSC，使计数频率方便换算
    
- **定时器通道选择**：
    
    - 普通PWM输出：选择`PWM Generation CHx`
        
    - 翻转模式：选择`Output Compare CHx`，Mode选择`Toggle on match`
        
    - 强制输出：在代码中动态切换模式
        
- **参数设置**：
    
    - Prescaler（预分频值）
        
    - Counter Mode（计数模式，通常为Up）
        
    - Counter Period（ARR值）
        
    - Pulse（CCR值，即Pulse值）
        
    - Output compare preload（预装载，翻转模式需禁用）
        
- **中断配置**：如需要使用翻转模式，需在NVIC中使能TIM全局中断
## 补充
### 1. **有效电平  ≠  引脚输出高电平**

“有效电平”和“无效电平”由OCxREF决定，再经过极性选择（CCxP）后才是最终输出到引脚的电平

	- 默认情况下，“有效=高电平”
	- 但如果你 `CCER` 寄存器里把极性选择位（CCxP）设为了1，那么“有效=低电平”
	
### 2.  **影子寄存器与预装载**
#### 2.1 **影子寄存器机制**
- ARR和CCRx寄存器都配有影子寄存器
- 修改这些寄存器的值不会立即生效，只有在一次更新事件（UEV）发生后才从影子寄存器更新到真实寄存器，这种设计可以防止在运行时突然改变输出参数导致异常

#### 2.2 **预装载使能配置**
- **OCxPE = 0**（禁用预装载）：写入CCRx的值立即生效，适用于需要动态实时改变输出的场景，如使用翻转模式实现PWM时需要注意：不能使能输出比较预装载功能，否则向CCR寄存器写入值不会立即生效
- **OCxPE = 1**（启用预装载）：写入CCRx的值暂存在预装载寄存器，等待更新事件到来后才生效

### 3. 资源冲突
同一个定时器中，输出比较和输入捕获**不能同时使用**，因为它们共用CCR寄存器和通道引脚。

### 4. 多通道独立频率
同一个定时器的4个通道**共享同一个时基单元**（PSC和ARR），因此它们输出PWM的频率是相同的。如果需要输出不同频率的PWM，必须使用不同的定时器
